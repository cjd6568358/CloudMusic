## 3. 反查规程（冻结，可直接执行）

> **2026-11-05 P2 实证修正（`14`）**：下方 ①~⑨ 流程不变，但「文件名全部混淆、只能先抠 `0x7f` ID 反查」的前提已被推翻——apktool 解包的 layout XML 根元素保留 `android:tag="layout/<原始语义名>_0"`，实测 **1,754 个语义名**、其中播放页相关 48 个。建议 ① 先扫 tag 建「语义名 → 混淆文件名 → `public.xml` id」映射，ID 反查降为交叉校验。
> 另实测 `PlayerActivity*.smali`（76 个文件）与 20 个播放页自定义 View 类**都没有内联 `0x7f` 资源常量**，自定义 View 分布在 `classes5/9/10/15/18.dex`（不在 classes14）。静态闭包（9 个入口 / 163 项资源 / 179 条边）与 40 个唱片旋转动画候选见 `14`；**代码侧 anim 注入仍挂账**，⑦ 导出前必须用 jadx 或真机确认具体 anim id。
> `tools/player_resource_audit.py` 已把 ④⑤⑥ 工具化，产物 `analysis/player-resource-closure.json/.csv`；本机完成的是 ①~⑥ 的静态反查，⑦~⑨ 仍待 Android SDK。

```
① 取 classes14.dex（Windows 本机用 tools/ 内置 7z；`unzip` 不一定可用）
   7z e -so NeteaseCloudMusic.apk classes14.dex > analysis/classes14.dex
   # 等价：unzip -p NeteaseCloudMusic.apk classes14.dex > analysis/classes14.dex

② 反汇编（tools/ 已有 baksmali 3.0.10）
   java -jar tools/baksmali-3.0.10.jar d analysis/classes14.dex -o analysis/smali14

③ 定位播放页与其自定义 View 的 smali
   analysis/smali14/com/netease/cloudmusic/activity/PlayerActivity.smali
   （同目录/同包下搜索 rotate / disc / needle / vinyl 相关类）

④ 抽取资源常量
   在 smali 中匹配  const(/16|/high16)? v\d+, 0x7f[0-9a-f]{6}
   → 得到引用的资源 id 集合

⑤ 反查 public.xml（analysis/decoded/res/values/public.xml）
   id → (type, name)，例如 0x7f010000 → anim/a

⑥ 递归闭包
   对得到的 layout / style / drawable XML，继续解析其中的 @anim/ @drawable/ @color/ @dimen/
   引用并重复 ⑤，直到不再有新增 id

⑦ 导出资源到 :ui-legacy/res/，统一加 legacy_ 前缀（§5），
   批量改写 smali/layout 中的 R 引用

⑧ 每导出一项，向 docs/assets-mapping.csv 追加一行（§4）

⑨ 编译验证：:ui-legacy 单独 assembleDebug，无 Resources$NotFoundException
```

**验收标准**（03-10 §10 T03~T07）：映射表每条 `legacy_name` 在 APK 中存在、在 `:ui-legacy` 中有对应文件、编译通过、播放页启动无资源异常。

## 5. 命名改写方案（方案 A，已定案）

导出时统一加 `legacy_` 前缀：

```
R.anim.a02        →  R.anim.legacy_a02
@drawable/b21     →  @drawable/legacy_b21
res/anim/a02.xml  →  res/anim/legacy_a02.xml
```

理由：混淆名（`a.xml` / `a0.webp`）过于通用，与 `:app` 或第三方库资源合并时极易撞名，且 R8 `shrinkResources` 可能误删。统一前缀后可用 `tools:keep="@anim/legacy_*"` 一次性保护（03-12 §2）。

改写范围：导出的资源**文件名** + layout/XML 内的引用 + smali/Java 代码里的 `R.*` 常量（由 03-10 §3.1 步骤 ⑦ 的脚本批量完成）。
