**模块**：`:engine-legacy`（照搬舱）、`:engine-api`、`:engine-bridge`、`:feature-player`
**层**：L2 / L2.5 / L4（架构文档 §4 / §5 / §10）

## 4. 稳定门面（`:engine-api`，完整签名）

```kotlin
// —— 门面：单实例 + 单一 handle（架构 §14 #4），但保留 handle 参数以便未来扩展
@JvmInline value class EngineHandle(val raw: Long)

enum class EngineState { IDLE, PREPARING, PLAYING, PAUSED, ENDED, ERROR }

data class EngineSource(
    val trackId: String,
    val mimeHint: String,
    val expectedLength: Long = -1L,   // -1 = 未知（chunked / 直链无 Content-Length）
)

data class EngineConfig(
    val sampleRateHz: Int = 0,        // 0 = 由内核探测
    val preferHardwareDecoder: Boolean = true,
    val bufferMs: Int = 2000,
    val autoSkipOnError: Boolean = true,   // PRD §6.1：解码失败自动跳下一首（可关）
)

interface IMusicEngine {
    fun prepare(source: EngineSource, config: EngineConfig): EngineHandle
    fun attachDataSource(handle: EngineHandle, ds: IDataSource)   // ★L2.5 注入统一字节流
    fun play(handle: EngineHandle)
    fun pause(handle: EngineHandle)
    fun stop(handle: EngineHandle)
    fun seek(handle: EngineHandle, positionMs: Long)
    fun setVolume(handle: EngineHandle, volume: Float)             // 0f..1f
    fun positionMs(handle: EngineHandle): Long
    fun durationMs(handle: EngineHandle): Long
    fun state(): Flow<EngineState>
    fun setQuality(handle: EngineHandle, quality: Int)            // 竞品能力透传
    fun attachAudioEffect(handle: EngineHandle, effectId: Int)    // 竞品能力透传
    fun release(handle: EngineHandle)
    fun lastError(): CloudMusicError?
}

/** 以下为 03-01 已定义的契约副本（定义在 :core-model，实现在 :engine-bridge），此处非新定义 */
interface IDataSource {
    fun open(offset: Long): Long                 // 返回总长度，-1 未知
    fun readAt(offset: Long, buf: ByteArray, len: Int): Int   // 0=EOF，-1=错误
    fun close()
    fun mimeHint(): String
}
```

**单例约束**：`IMusicEngine` 由 Hilt `@Singleton` 提供，全局唯一实例；`EngineHandle` 同一时刻只允许存在一个有效值，`prepare()` 新曲目时必须先 `release()` 旧 handle。`PlaybackService` 持有它（架构 §10）。

## 5. `EngineAdapter`（舱内，门面 ↔ 竞品 SDK 映射）

| `IMusicEngine` | 竞品类 / JNI | 备注 |
|---|---|---|
| `prepare` | `PlaybackEngine.create()` + `Playback` | 构造单一会话，返回 `EngineHandle` |
| `attachDataSource` | `PlaybackDataSource` / `DataProvider` | 把 `IDataSource` 包成竞品接口（见下） |
| `play/pause/stop/seek` | `AudioPlayerUnit.nativePlay/nativePause/nativeStop/nativeSeek` | 报告 §2 已确认符号 |
| `positionMs/durationMs` | `Playback.getPosition()/getDuration()` | 毫秒统一 |
| `setVolume` | `nativeSetVolume` | 0..1 → 竞品量程转换 |
| `state()` | `PlaybackListener` 回调 → `MutableStateFlow` | 舱内把回调转成 Flow |
| `setQuality/attachAudioEffect` | `nativeChangeQuality` / `nativeAttachAudioEffect` | 透传，V0.1 不启用 |
| `release` | `Playback.release()` | 必须同时 `IDataSource.close()` |

**`IDataSource → PlaybackDataSource` 适配**（舱内核心）：

```kotlin
class LegacyDataSourceBridge(private val ds: IDataSource) : PlaybackDataSource {
    private var length = -1L
    override fun open(offset: Long): Long { length = ds.open(offset); return length }
    override fun read(offset: Long, buffer: ByteArray, size: Int): Int =
        ds.readAt(offset, buffer, size)
    override fun close() = ds.close()
    override fun getMimeType(): String = ds.mimeHint()
}
```

> 若反编译后竞品 `PlaybackDataSource` 的方法名/签名与上面不一致，**以实际 dex 为准**改适配层，不改 `IDataSource`。这正是保留门面的价值。

## 7. `:engine-bridge` —— 三态 `IDataSource` 实现

`DataSourceAdapter.from(link, args)` 是唯一入口，**只按 `Link.kind` 分派**（03-01 §5）。

| kind | 实现 | 要点 |
|---|---|---|
| URL | `HttpDataSource` | OkHttp 4.x；透传 `Link.headers`；`Range: bytes={offset}-`；302 跟随；超时 10s 连接 / 30s 读 |
| LOCAL | `FileDataSource` | `contentResolver.openFileDescriptor(uri,"r")`；`FileInputStream.channel.position(offset)`；关闭时释放 FD |
| PROXIED | `DriverDataSource` | 由驱动直接提供带鉴权的流（WebDAV Basic/Digest、SFTP/FTP/NFS）；**不经 nanohttpd**（架构 §5） |
| TEXT | `MemoryDataSource` | `text.encodeToByteArray()`；`open` 返回字节数；`readAt` 用 `copyInto` |

### 7.1 统一实现骨架

```kotlin
abstract class BaseDataSource : IDataSource {
    protected var total: Long = -1L
    protected var closed = false
    final override fun readAt(offset: Long, buf: ByteArray, len: Int): Int {
        check(!closed) { "DataSource 已关闭" }
        require(offset >= 0 && len >= 0 && len <= buf.size)
        if (len == 0) return 0
        return try { readAtInternal(offset, buf, len) }
        catch (e: Exception) { lastError = e.toCloudMusicError(); -1 }
    }
    protected abstract fun readAtInternal(offset: Long, buf: ByteArray, len: Int): Int
    final override fun close() { if (!closed) { closed = true; closeInternal() } }
    protected abstract fun closeInternal()
}
```

### 7.2 Seek / Range 关键规则

- `open(offset)` 的 `offset` 是**首次读取位置**（拖动进度时非 0）；返回总长度，`-1` 表示未知。
- 未知长度时 `durationMs()` 返回 `-1`，UI 进度条显示为不可拖动，不伪造时长。
- `readAt` 返回 `0` 表示 EOF，`-1` 表示错误；**上层不得把 -1 当 EOF**（会死循环）。
- 网络源每次 `readAt` 允许重连，但必须复用同一 `Link`；直链过期抛 `E_LINK_EXPIRED`，不静默重试超过 2 次。
- `requireReference=true` 的 `Link`（SFTP/FTP/NFS）在 `close()` 时释放底层句柄（对齐 Go `SyncClosers`）。
- 所有实现必须**线程安全**：`readAt` 可能被内核解码线程调用，而 `close()` 来自 `EngineThread`；用 `@Synchronized` 或 `AtomicBoolean` 保护。

## 8. 播放队列（双轨设计）

竞品队列状态机在 `libnmplaylist.so`（报告 §2 的 `PlaylistJniBridge` 约 30 个 JNI 方法）。本项目**不自研队列状态机**，但要保证冷启动恢复与 UI 拖拽，故采用双轨：

| 轨道 | 归属 | 职责 | 真相源 |
|---|---|---|---|
| 业务队列 | `:feature-player` + Room | 顺序、播放模式、拖拽排序、插播、收藏、跨来源混合、冷启动恢复 | ✅ **唯一真相源** |
| Native 队列 | `libnmplaylist.so`（舱内） | 播放执行镜像、随机算法、最近播放 | ❌ 只读镜像 |

**同步规则**：业务队列变更后由 `QueueSync` **单向全量下发**到 native 队列；**禁止**反向读 native 队列回写业务态（避免双写冲突）。随机模式由业务层生成顺序后下发，不依赖 native 的随机实现。

### 8.1 Room 表

```sql
CREATE TABLE queue_items (
    queue_id      TEXT NOT NULL DEFAULT 'default',
    position      INTEGER NOT NULL,
    track_id      TEXT NOT NULL,
    source_ref    TEXT NOT NULL,      -- SourceRef 序列化 JSON
    added_at      INTEGER NOT NULL,
    PRIMARY KEY (queue_id, position)
);
CREATE INDEX idx_queue_track ON queue_items(track_id);

CREATE TABLE playback_state (
    id            INTEGER PRIMARY KEY CHECK (id = 1),
    current_track_id TEXT,
    position_ms   INTEGER NOT NULL DEFAULT 0,
    play_mode     TEXT NOT NULL,      -- SEQUENCE / SINGLE_LOOP / LIST_LOOP / SHUFFLE
    updated_at    INTEGER NOT NULL
);
```

### 8.2 队列 API

```kotlin
enum class PlayMode { SEQUENCE, SINGLE_LOOP, LIST_LOOP, SHUFFLE }

interface QueueRepository {
    fun observe(): Flow<List<QueueItem>>
    suspend fun setAll(tracks: List<Track>)              // 全量替换（下发 native）
    suspend fun insertNext(track: Track)                 // 插播
    suspend fun move(from: Int, to: Int)                 // 拖拽排序
    suspend fun remove(position: Int)
    suspend fun clear()
    suspend fun saveCursor(trackId: String, positionMs: Long)   // 每 5s + 切歌/暂停时
    suspend fun restore(): PlaybackSnapshot?             // 冷启动恢复
}

class QueueSync @Inject constructor(
    private val engine: IMusicEngine, private val repo: QueueRepository
) { suspend fun push(items: List<QueueItem>, mode: PlayMode, startAt: Int) { /* 调 PlaylistJniBridge 快照接口 */ } }
```

**恢复顺序**（冷启动）：`Room.restore()` → 重建 `Track` → `QueueSync.push()` → `prepare(current)` → `seek(savedPositionMs)` → **保持暂停态**，等用户点播放（PRD §6.1 不自动开播）。

## 9. `PlayerController` 状态机

```
                 ┌──────────┐
   resolve() ──▶ │ PREPARING│ ── 成功 ──▶ PLAYING ⇄ PAUSED
                 └────┬─────┘                 │  │
                      │ 失败                  │  └── ENDED → 下一首 / 列表结束
                      ▼                        │
                   ERROR ── 自动跳下一首 ──────┘
                      │
                      └── 输出切换 DLNA：PAUSED(静音) + 手机转遥控器
```

| 事件 | 来源 | 动作 |
|---|---|---|
| `Play(track)` | UI / 队列 | `resolve → link → attachDataSource → prepare → play` |
| `Pause / Resume` | UI / `IMediaControl`（03-07 照搬舱） | `engine.pause/play` |
| `Seek(ms)` | UI / 通知 / AVRCP | `engine.seek` |
| `Next / Prev` | UI / 线控 | 业务队列取下一项 → 重新 `prepare` |
| `FocusLost / Duck / Regain` | `IMediaControl.onFocusChange` | 暂停 / 降音量 / 恢复（**由照搬层裁决**，见 §11） |
| `OutputChanged(device)` | `OutputRouter`（03-08） | DLNA 时内核静音；回落本机时恢复 |
| `EngineError(e)` | `IMusicEngine.lastError()` | 记录失败 → 自动跳下一首（可关）→ UI 提示具体原因 |
| `NativeCrashed` | 进程退出后系统重启服务（`START_STICKY`） | §12.6 |

**状态广播**：`StateFlow<PlayerState>` 单向推给 UI（03-10）与 `IMediaControl.publishMetadata/setPlaybackState`；UI **不得**直接调用 `IMusicEngine`。

## 10. 线程模型（架构 §10）

| 线程 | 职责 | 约束 |
|---|---|---|
| `Main` | Compose UI、`IMediaControl` 回调入口 | 不做 IO、不调 native |
| `PlaybackService`（前台服务） | 持有 `IMusicEngine`、`QueueSync`、`OutputRouter` | `foregroundServiceType=mediaPlayback` |
| `EngineThread`（单线程 `Executors.newSingleThreadExecutor`） | **所有 `IMusicEngine` 调用串行化** | 竞品 native 引擎非线程安全，禁止并发调用 |
| `IoDispatcher` | `link()`、`IDataSource` 网络读、Room 读写 | 协程 |
| `DecodeThread`（舱内自管） | so 内部解码/输出，`readAt` 回调来源 | 由舱管理，桥接实现须线程安全 |

- `EngineThread` 上的调用统一包成 `suspend fun <T> onEngine(block: () -> T): T = withContext(engineDispatcher) { block() }`。
- 状态收集：`engine.state().flowOn(engineDispatcher)`，UI 在 `Main` 收集。
- 禁止在 `EngineThread` 做 `link()` 网络请求（会阻塞播放指令）。

## 12. 关键时序

### 12.1 点播一首混合曲库里的歌
```
UI Play(track) → PlayerController.resolve(track)
 → DriverRegistry.get(storageId).get(path).link(...) → Link
 → DataSourceAdapter.from(link) → IDataSource
 → onEngine { engine.prepare(...); engine.attachDataSource(handle, ds); engine.play(handle) }
 → state: PREPARING → PLAYING → StateFlow → UI + IMediaControl.publishMetadata
```

### 12.2 拖动进度
```
Seek(ms) → onEngine { engine.seek(handle, ms) }
 → 舱内按新位置调用 ds.readAt(offset>0, ...)
 → HttpDataSource 发 Range 请求 / FileDataSource 移动 channel.position
 → 缓冲后恢复 PLAYING
```

### 12.3 切歌 / 自动下一首
```
ENDED 或 ERROR(autoSkip) → QueueRepository.next(mode)
 → onEngine { engine.release(oldHandle) }  ← 同时 ds.close()
 → 重新 12.1
```

### 12.4 来电 / 焦点变化（照搬层主导）
```
IMediaControl.onFocusChange(LOSS) → PlayerController.pauseFromFocus()
 → onEngine { engine.pause() } → setPlaybackState(PAUSED)
焦点恢复 GAIN → resumeFromFocus() → play
```

### 12.5 冷启动恢复
```
PlaybackService.onCreate → QueueRepository.restore()
 → QueueSync.push(items, mode, startAt) → prepare(current) → seek(savedMs)
 → 保持 PAUSED，UI 显示上次曲目与进度
```

### 12.6 native crash 恢复（2026-11-04 语义修正：进程级恢复，非进程内捕获）

> 单进程下引擎 so 的 native crash（SIGSEGV/SIGABRT）即**整个进程退出**；进程内 signal handler 捕获后继续运行属未定义行为，且与 `debuggerd`/tombstoned 冲突，**禁止**作为架构承诺（`10 §2 R2`）。

```
PlaybackService 声明 START_STICKY（onStartCommand 返回值）
  → 引擎 native crash ⇒ 进程退出（tombstoned 落盘记录）
  → 系统重启服务：
      · Android 12+ 后台 FGS 限制：onCreate 内立即 startForeground；
        若被系统拒绝，先完成数据恢复，等用户交互后再开播
  → onCreate：crash 标记文件检测「上次异常退出」
        （引擎加载时写入、优雅关闭时清除）→ 记录 E_ENGINE_NATIVE_CRASH
      → QueueRepository.restore() → 队列与进度从 Room 游标恢复，保持 PAUSED
  → UI 提示「播放已恢复」
```

- **验收口径**：G09 = 注入 crash 后「服务重启完成、队列/进度一致、≤5s 回到可播放态」。
- 竞品用独立 `:play` 进程隔离引擎崩溃；本项目单进程**明确放弃**该隔离，换来无 AIDL 的简单模型（架构 §1）。若真机体验不可接受，`IMusicEngine` 门面允许后续把 `:engine-legacy` 拆为独立进程（预留，V0.1 不做）。

## 13. 错误与降级

| 错误码 | 触发 | 处理 |
|---|---|---|
| `E_LINK_EXPIRED` | strm 直链 403/超时 | 标 `Track.availability=LINK_EXPIRED`，自动跳下一首，不删条目 |
| `E_DS_UNREACHABLE` | WebDAV/NAS 断连 | 标 `UNREACHABLE`，灰显，恢复后自动置 OK |
| `E_ENGINE_DECODE` | 解码失败 | 提示格式/文件损坏，自动跳下一首 |
| `E_ENGINE_ABI_MISSING` | ABI 验收未过 | **构建期阻断**，不进运行时 |
| `E_ENGINE_NATIVE_CRASH` | so 崩溃（进程随之退出） | §12.6：`START_STICKY` 重启 + Room 游标恢复 |

**失败记录入口**：`failure_log` 表（trackId / code / detail / 时间），设置页可查看与「批量重试」。上游人类可读消息经 `DriverCtx.errDetail` 透传，禁止显示笼统「播放失败」。

## 16. 明确禁止事项

1. 禁止在 `:engine-legacy` 之外的任何模块 import `com.netease.*`。
2. 禁止并发调用 `IMusicEngine`（一律经 `EngineThread` 串行）。
3. 禁止把 `Link` 对象缓存进 Room / 队列（只存 `SourceRef`，用时重建）。
4. 禁止反向从 native 队列读回业务态（单向同步）。
5. 禁止因播放失败删除 `Track` 或清空队列。
6. 禁止为本机播放启动 nanohttpd 代理。
7. 禁止在运行时做 so 指纹校验（一次性验收即可）。
8. 禁止把 `Addition` 里的账号密码写进日志或崩溃上报。
