## 1. 模块组成与职责边界

| module | 职责 | 是否照搬 |
|---|---|---|
| `:engine-legacy` | 竞品 Java SDK 层 + 167 个 arm64 so；实现 `IMusicEngine` | ✅ 照搬（jadx 重建源码） |

## 4. 稳定门面（`:engine-api`，完整签名）

> **★ 2026-11-05 已落地（12 §14）**：下方签名已变成 `engine-api/src/main/kotlin/com/example/cloudmusic/engine/api/EngineApi.kt` 的可编译代码（`IMusicEngine` 14 个方法逐字对齐，`tools/check_source_contracts.py` 静态校验签名不漂移），并附 `InMemoryMusicEngine` 内存参考实现与 12 个单测（含 §15 T06 单一 handle、T09 seek 钳制）。`13 §7` 实证的舱内 `PlaybackEngine` / `DataProvider` / `PlayerDataSource` 细节**一律封装在舱内 `EngineAdapter`，不得泄漏到本门面**。

```kotlin
// —— 门面：单实例 + 单一 handle（架构 §14 #4），但保留 handle 参数以便未来扩展
@JvmInline value class EngineHandle(val raw: Long)

enum class EngineState { IDLE, PREPARING, PLAYING, PAUSED, ENDED, ERROR }

data class EngineSource(
    val trackId: String,
    val mimeHint: String,
    val expectedLength: Long = -1L,   // -1 = 未知（chunked / 直链无 Content-Length）
)

data class EngineConfig(
    val sampleRateHz: Int = 0,        // 0 = 由内核探测
    val preferHardwareDecoder: Boolean = true,
    val bufferMs: Int = 2000,
    val autoSkipOnError: Boolean = true,   // PRD §6.1：解码失败自动跳下一首（可关）
)

interface IMusicEngine {
    fun prepare(source: EngineSource, config: EngineConfig): EngineHandle
    fun attachDataSource(handle: EngineHandle, ds: IDataSource)   // ★通用取流注入端口（§61.108 语义定稿）：url/localPath 经 EngineSource 直传（C-05）；proxy 态回源注入是 A 路线语义；B2（Media3EngineAdapter）主路径不经此口，适配器仅保存引用 + release 时关闭，预留未来自定义字节流注入
    fun play(handle: EngineHandle)
    fun pause(handle: EngineHandle)
    fun stop(handle: EngineHandle)
    fun seek(handle: EngineHandle, positionMs: Long)
    fun setVolume(handle: EngineHandle, volume: Float)             // 0f..1f
    fun positionMs(handle: EngineHandle): Long
    fun durationMs(handle: EngineHandle): Long
    fun state(): Flow<EngineState>
    fun setQuality(handle: EngineHandle, quality: Int)            // 竞品能力透传
    fun attachAudioEffect(handle: EngineHandle, effectId: Int)    // 竞品能力透传
    fun release(handle: EngineHandle)
    fun lastError(): CloudMusicError?
}

/** 以下为 03-01 已定义的契约副本（定义在 :core-model，实现在 :engine-bridge），此处非新定义 */
interface IDataSource {
    fun open(offset: Long): Long                 // 返回总长度，-1 未知
    fun readAt(offset: Long, buf: ByteArray, len: Int): Int   // 0=EOF，-1=错误
    fun close()
    fun mimeHint(): String
}
```

**单例约束**：`IMusicEngine` 由 Hilt `@Singleton` 提供，全局唯一实例；`EngineHandle` 同一时刻只允许存在一个有效值，`prepare()` 新曲目时必须先 `release()` 旧 handle。`PlaybackService` 持有它（架构 §10）。

**`IDataSource / Link → DataProvider` 适配**（舱内核心，**2026-11-05 spike #1 按实际 dex 重写，见 `13 §3`**）：

> 实证结论：原假设的 `PlaybackDataSource.open/read/close/getMimeType` **不存在**。该类是 `public final` 的预加载 / 引擎缓存配置 JNI 桥（7 个 native 方法：`nativePreload` / `nativeCancelPreload` / `nativeRelease` / `nativeRetainEngineCacheLoadConfigHandle` / `nativeReleaseEngineCacheLoadConfigHandle` / `nativeSetEngineCacheLoadConfig` / `nativeSetPreloadCallback`），公开 API 为 `preload(J)` / `cancelPreload()` / `close()` / `setEngineCacheLoadConfig(...)` / `getMusicInfo()` 等。真正的音源接口是 `com.netease.cloudmusic.android.sdk.playerengine.DataProvider`（`classes14.dex` 的 `public interface abstract`，9 个方法）：
> `getUrl(): UrlResult`、`getLocalPath(): String`、`openLocalFd(String): Int`、`closeLocalFd(Int)`、`onExpire(String): UrlResult`、`setDataRequestErrorCallback(DataRequestErrorCallback, Boolean)`、`createDataRequestHandler(): Object`、`cancelRequest()`、`close()`。`UrlResult` 是 6 字段 Kotlin data class（`url / fileSize / format / expiresAt / realBitrate / md5`）。

```kotlin
// 示意：字段与构造以实际 dex 为准；竞品 native 自己读 URL / fd，Java 层不喂字节流
class LegacyDataSourceBridge(
    private val link: Link,
    private val ds: IDataSource,
    private val proxy: LocalHttpStreamProxy,
) : DataProvider {
    override fun getUrl(): UrlResult = when (link.kind) {
        Link.Kind.URL     -> UrlResult(url = link.url, fileSize = ds.length(), /* ... */)
        Link.Kind.PROXIED -> UrlResult(url = proxy.resolve(link), /* ... */)
        else              -> UrlResult(url = "", /* ... */)   // LOCAL 走 getLocalPath / openLocalFd
    }
    override fun getLocalPath(): String = link.localPath.orEmpty()
    override fun openLocalFd(path: String): Int = fdOpener.open(path)   // SAF / 文件路径
    override fun closeLocalFd(fd: Int) = fdOpener.close(fd)
    override fun onExpire(oldUrl: String): UrlResult = getUrl()          // 403 / 签名过期：重签或回落代理
    override fun setDataRequestErrorCallback(cb: DataRequestErrorCallback, enable: Boolean) { /* 07 §8 透传 */ }
    override fun createDataRequestHandler(): Any = TODO("以实际 dex 为准")
    override fun cancelRequest() = ds.close()
    override fun close() = ds.close()
}
```

> **`IDataSource` 契约不变**：`open(offset) / readAt() / mimeHint()` 是 03-01 §3 的自研契约，03-08 的本地 HTTP 流代理仍直接消费它；舱内只负责把 `Link` 三态翻译成 `DataProvider` 的 URL / fd / 重签语义。这正是保留门面的价值。
>
> **`13 §7.3` 补接入链**：`PlayerDataSource` 是非 native 的 Kotlin 数据类（`getDataProvider(): DataProvider`、`getResourceInfo()`、`getConfig()`、`getSongId()`、`getSourceCallback()`）。上面的 `LegacyDataSourceBridge : DataProvider` 结论成立，但要再包一层：
> `Link 三态 → LegacyDataSourceBridge(DataProvider) → PlayerDataSource → nativeEngineSetDataSource(handle, playerDataSource)`。
> `DataProvider` 面向缓存 / 网络层，`PlayerDataSource` 才是直接喂播放器的封装，两者不是二选一。
>
> **`13 §6 #4` 已收口**：全表 8 行均已按实际 dex 复核（`13 §7.2`）；剩余挂账见 `13 §6`（NMCommonCache 类方法名解析偏移、JNI 差 8 两组方法的注册方式确认）。一次性 ABI 验收（`§6`）可用 `tools/engine_api_audit.py` 的逐类差集替代笼统符号计数。
>
> **★ 2026-11-06 复核补注（`16 §3`）**：上表 `getUrl()` 对 `PROXIED` 返回 `proxy.resolve(link)` 意味着——**WebDAV 鉴权流等无直链形态音源的本机播放必须启动本地代理**（引擎回环自取代理 URL）。这推翻了「本机播放不经 nanohttpd」的旧口径（架构 §5/§7.4、03-01 §5、本文 §7 / §16 #6、03-08 §1 / §8.4 / §14 #1），各处已按 `16 §3` 同日修正；`:output-localproxy` 的 `ProxyStartPolicy` 已按 03-08 §8.4 落地 ④ 触发器（C-06，第十二批见 `12 §21`）。

## 7. `:engine-bridge` —— 三态 `IDataSource` 实现

> **★ 2026-11-06 已落地（`12 §22` / `16 §5.3 T-P2`）**：本节四态实现与 §7.1 骨架已变成
> `engine-bridge/` 下的纯 JVM 可编译代码（`DataSourceAdapter` / `BaseDataSource` / 四个 DataSource），
> `03-06 §15 T01~T05` 由 `DataSourceAdapterTest` 覆盖，另补 EOF 与 `-1` 区分、Range 透传、并发读。
> `RangeHttpStack`（OkHttp）与 `FdOpener`（`ContentResolver.openFileDescriptor`）的**生产端口仍属 Android 侧**，
> 由 `:core-di` 注入；舱内 `EngineAdapter` 与 `LegacyDataSourceBridge : DataProvider` 仍待 T-L / jadx。

`DataSourceAdapter.from(link, args)` 是唯一入口，**只按 `Link.kind` 分派**（03-01 §5）。其产出 `IDataSource` 的消费方是**本地代理回源与扫描 Range 读**，不在引擎主取流路径（`13 §3` 实证；引擎侧由 `LegacyDataSourceBridge : DataProvider` 另行交付 URL / 路径 / fd，见 §5）。

| kind | 实现 | 要点 |
|---|---|---|
| URL | `HttpDataSource` | OkHttp 4.x；透传 `Link.headers`；`Range: bytes={offset}-`；302 跟随；超时 10s 连接 / 30s 读 |
| LOCAL | `FileDataSource` | `contentResolver.openFileDescriptor(uri,"r")`；`FileInputStream.channel.position(offset)`；关闭时释放 FD |
| PROXIED | `DriverDataSource` | 驱动提供带鉴权的流；**经本地代理回环回源**（本机播放与投屏同路，2026-11-06 修正，`16 §3`） |
| TEXT | `MemoryDataSource` | `text.encodeToByteArray()`；`open` 返回字节数；`readAt` 用 `copyInto` |

### 7.1 统一实现骨架

```kotlin
abstract class BaseDataSource : IDataSource {
    protected var total: Long = -1L
    protected var closed = false
    final override fun readAt(offset: Long, buf: ByteArray, len: Int): Int {
        check(!closed) { "DataSource 已关闭" }
        require(offset >= 0 && len >= 0 && len <= buf.size)
        if (len == 0) return 0
        return try { readAtInternal(offset, buf, len) }
        catch (e: Exception) { lastError = e.toCloudMusicError(); -1 }
    }
    protected abstract fun readAtInternal(offset: Long, buf: ByteArray, len: Int): Int
    final override fun close() { if (!closed) { closed = true; closeInternal() } }
    protected abstract fun closeInternal()
}
```

### 7.2 Seek / Range 关键规则

- `open(offset)` 的 `offset` 是**首次读取位置**（拖动进度时非 0）；返回总长度，`-1` 表示未知。
- 未知长度时 `durationMs()` 返回 `-1`，UI 进度条显示为不可拖动，不伪造时长。
- `readAt` 返回 `0` 表示 EOF，`-1` 表示错误；**上层不得把 -1 当 EOF**（会死循环）。
- 网络源每次 `readAt` 允许重连，但必须复用同一 `Link`；直链过期抛 `E_LINK_EXPIRED`，不静默重试超过 2 次。
- `requireReference=true` 的 `Link`（SFTP/FTP/NFS）在 `close()` 时释放底层句柄（对齐 Go `SyncClosers`）。
- 所有实现必须**线程安全**：`readAt` 可能被内核解码线程调用，而 `close()` 来自 `EngineThread`；用 `@Synchronized` 或 `AtomicBoolean` 保护。

## 8. 播放队列（双轨设计）

> **★ 2026-11-06 已落地（`12 §23` / `16 §5.3 T-P1`）**：本节 §8.1 两表模型、§8.2 的
> `PlayMode` / `QueueRepository` / `QueueSync` 与 §9 `PlayerController` 状态机已变成
> `feature-player/` 下的纯 JVM 可编译代码，T07 / T08 / T11 由 `PlayerControllerTest` 覆盖。
> **2026-11-06 第十七批（`12 §26`，T-A1）**：`queue_items` / `playback_state` 的 Room 真实持久化已落在
> `:core-di/db`（`RoomQueueRepository` 实现 `QueueRepository`，冷启动恢复读 `playback_state` 单行），
> `LibraryModule` 已从内存绑定换绑；`PlaylistJniBridge` 生产下发仍属 T-L；
> `NativeQueueSandbox` 已把 `13 §4` 的四条隔离约束登记为自检常量。

竞品队列状态机在 `libnmplaylist.so`（报告 §2 的 `PlaylistJniBridge` 约 30 个 JNI 方法）。本项目**不自研队列状态机**，但要保证冷启动恢复与 UI 拖拽，故采用双轨：

| 轨道 | 归属 | 职责 | 真相源 |
|---|---|---|---|
| 业务队列 | `:feature-player` + Room | 顺序、播放模式、拖拽排序、插播、收藏、跨来源混合、冷启动恢复 | ✅ **唯一真相源** |
| Native 队列 | `libnmplaylist.so`（舱内） | 播放执行镜像、随机算法、最近播放 | ❌ 只读镜像 |

**同步规则**：业务队列变更后由 `QueueSync` **单向全量下发**到 native 队列；**禁止**反向读 native 队列回写业务态（避免双写冲突）。随机模式由业务层生成顺序后下发，不依赖 native 的随机实现。

> **2026-11-05 spike #1 实证补强（`13 §4`，对应 `10 §4 #5`）**：上表把 native 队列称为「只读镜像」是**设计目标而非竞品现状**。ELF `.rodata` 直读确认 `libnmplaylist.so` 自带完整 SQLite 持久化 —— 5 张表（`playlist_current_pointer` / `playlist_music_item` / `playlist_snapshot` / `playlist_snapshot_gc_queue` / `playlist_store_meta`）、`sqlite3_open`、以及 `nativeInit(db_path)` / `nativeSetDbAdapter` / `nativeRestoreFromDb` / `nativePersistList` / `nativeUpdatePlaybackPosition` 等 25 个 `PlaylistJniBridge` 导出；`db_path` 由 Java 层传入，`libsqlite3x.so` 是 requery SQLite 独立打包版。为维持「Room 唯一真相源」，舱内必须：
> 1. `nativeInit` 只传**隔离沙箱路径**（`noBackupFilesDir/native_playlist/` 或 `cacheDir`），明确为执行镜像缓存，不参与业务恢复；
> 2. **禁止**调用 `nativeRestoreFromDb()` / `nativeListRecentPlaylists()` 回写业务态；冷启动恢复唯一入口是 `Room.restore()` → `QueueSync.push()`；
> 3. 每次实例初始化先全量 `push` 覆盖 native 残留，避免上次会话快照被当成当前队列；
> 4. Room 8 表与 native 5 表**物理隔离、无跨库外键**，且都不得存明文凭据（凭据只在 DataStore）。

## 9. `PlayerController` 状态机

```
                 ┌──────────┐
   resolve() ──▶ │ PREPARING│ ── 成功 ──▶ PLAYING ⇄ PAUSED
                 └────┬─────┘                 │  │
                      │ 失败                  │  └── ENDED → 下一首 / 列表结束
                      ▼                        │
                   ERROR ── 自动跳下一首 ──────┘
                      │
                      └── 输出切换 DLNA：PAUSED(静音) + 手机转遥控器
```

| 事件 | 来源 | 动作 |
|---|---|---|
| `Play(track)` | UI / 队列 | `resolve → link → attachDataSource → prepare → play` |
| `Pause / Resume` | UI / `IMediaControl`（03-07 照搬舱） | `engine.pause/play` |
| `Seek(ms)` | UI / 通知 / AVRCP | `engine.seek` |
| `Next / Prev` | UI / 线控 | 业务队列取下一项 → 重新 `prepare` |
| `FocusLost / Duck / Regain` | `IMediaControl.onFocusChange` | 暂停 / 降音量 / 恢复（**由照搬层裁决**，见 §11） |
| `OutputChanged(device)` | `OutputRouter`（03-08） | DLNA 时内核静音；回落本机时恢复 |
| `EngineError(e)` | `IMusicEngine.lastError()` | 记录失败 → 自动跳下一首（可关）→ UI 提示具体原因 |
| `NativeCrashed` | 进程退出后系统重启服务（`START_STICKY`） | §12.6 |

**状态广播**：`StateFlow<PlayerState>` 单向推给 UI（03-10）与 `IMediaControl.publishMetadata/setPlaybackState`；UI **不得**直接调用 `IMusicEngine`。

## 10. 线程模型（架构 §10）

| 线程 | 职责 | 约束 |
|---|---|---|
| `Main` | Compose UI、`IMediaControl` 回调入口 | 不做 IO、不调 native |
| `PlaybackService`（前台服务） | 持有 `IMusicEngine`、`QueueSync`、`OutputRouter` | `foregroundServiceType=mediaPlayback` |
| `EngineThread`（单线程 `Executors.newSingleThreadExecutor`） | **所有 `IMusicEngine` 调用串行化** | 竞品 native 引擎非线程安全，禁止并发调用 |
| `IoDispatcher` | `link()`、`IDataSource` 网络读、Room 读写 | 协程 |
| `DecodeThread`（舱内自管） | so 内部解码/输出，`readAt` 回调来源 | 由舱管理，桥接实现须线程安全 |

- `EngineThread` 上的调用统一包成 `suspend fun <T> onEngine(block: () -> T): T = withContext(engineDispatcher) { block() }`。
- 状态收集：`engine.state().flowOn(engineDispatcher)`，UI 在 `Main` 收集。
- 禁止在 `EngineThread` 做 `link()` 网络请求（会阻塞播放指令）。

## 12. 关键时序

### 12.1 点播一首混合曲库里的歌
```
UI Play(track) → PlayerController.resolve(track)
 → DriverRegistry.get(storageId).get(path).link(...) → Link
 → 按 Link.kind 交付（§5 DataProvider 桥接）：
     url/localPath → EngineSource 填 url/localPath（C-05），引擎自取
     proxy         → 先 proxy.publish(trackId, link) 拿回环 URL（03-08 §8.4 ④），
                     EngineSource.url 填代理 URL；ds 供代理回源
 → onEngine { engine.prepare(...); engine.attachDataSource(handle, ds); engine.play(handle) }
 → state: PREPARING → PLAYING → StateFlow → UI + IMediaControl.publishMetadata
```

### 12.2 拖动进度
```
Seek(ms) → onEngine { engine.seek(handle, ms) }
 → 引擎按新位置拉流：url 态 native 自发 Range 请求；
   proxy 态经代理 URL 的 Range 请求 → 代理回源 readAt(offset>0)
   （HttpDataSource 发 Range 请求 / FileDataSource 移动 channel.position）
 → 缓冲后恢复 PLAYING
```

### 12.3 切歌 / 自动下一首
```
ENDED 或 ERROR(autoSkip) → QueueRepository.next(mode)
 → onEngine { engine.release(oldHandle) }  ← 同时 ds.close()
 → 重新 12.1
```

### 12.4 来电 / 焦点变化（照搬层主导）
```
IMediaControl.onFocusChange(LOSS) → PlayerController.pauseFromFocus()
 → onEngine { engine.pause() } → setPlaybackState(PAUSED)
焦点恢复 GAIN → resumeFromFocus() → play
```

### 12.5 冷启动恢复
```
PlaybackService.onCreate → QueueRepository.restore()
 → QueueSync.push(items, mode, startAt) → prepare(current) → seek(savedMs)
 → 保持 PAUSED，UI 显示上次曲目与进度
```

### 12.6 native crash 恢复（2026-11-04 语义修正：进程级恢复，非进程内捕获）

> 单进程下引擎 so 的 native crash（SIGSEGV/SIGABRT）即**整个进程退出**；进程内 signal handler 捕获后继续运行属未定义行为，且与 `debuggerd`/tombstoned 冲突，**禁止**作为架构承诺（`10 §2 R2`）。

```
PlaybackService 声明 START_STICKY（onStartCommand 返回值）
  → 引擎 native crash ⇒ 进程退出（tombstoned 落盘记录）
  → 系统重启服务：
      · Android 12+ 后台 FGS 限制：onCreate 内立即 startForeground；
        若被系统拒绝，先完成数据恢复，等用户交互后再开播
  → onCreate：crash 标记文件检测「上次异常退出」
        （引擎加载时写入、优雅关闭时清除）→ 记录 E_ENGINE_NATIVE_CRASH
      → QueueRepository.restore() → 队列与进度从 Room 游标恢复，保持 PAUSED
  → UI 提示「播放已恢复」
```

- **验收口径**：G09 = 注入 crash 后「服务重启完成、队列/进度一致、≤5s 回到可播放态」。
- 竞品用独立 `:play` 进程隔离引擎崩溃；本项目单进程**明确放弃**该隔离，换来无 AIDL 的简单模型（架构 §1）。若真机体验不可接受，`IMusicEngine` 门面允许后续把 `:engine-legacy` 拆为独立进程（预留，V0.1 不做）。

## 13. 错误与降级

| 错误码 | 触发 | 处理 |
|---|---|---|
| `E_LINK_EXPIRED` | strm 直链 403/超时 | 标 `Track.availability=LINK_EXPIRED`，自动跳下一首，不删条目 |
| `E_DS_UNREACHABLE` | WebDAV/NAS 断连 | 标 `UNREACHABLE`，灰显，恢复后自动置 OK |
| `E_ENGINE_DECODE` | 解码失败 | 提示格式/文件损坏，自动跳下一首 |
| `E_ENGINE_ABI_MISSING` | ABI 验收未过 | **构建期阻断**，不进运行时 |
| `E_ENGINE_NATIVE_CRASH` | so 崩溃（进程随之退出） | §12.6：`START_STICKY` 重启 + Room 游标恢复 |

**失败记录入口**：`failure_log` 表（trackId / code / detail / 时间），设置页可查看与「批量重试」。上游人类可读消息经 `DriverCtx.errDetail` 透传，禁止显示笼统「播放失败」。

## 16. 明确禁止事项
