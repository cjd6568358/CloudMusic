## 1. 职责与边界

| 做 | 不做 |
|---|---|
| 照搬竞品 AudioFocus 状态机（抢占/duck/恢复） | 不引入 Media3、不自己重写焦点逻辑 |
| 照搬媒体按键分发、MediaSession 元数据与播放状态 | 不解码、不维护播放队列（03-06） |
| 通知栏媒体卡片、锁屏控制、AVRCP 元数据 | 不做厂商推送 / 角标 / 车机深度适配 |
| 对外暴露 `IMediaControl` 自研门面 | 不让任何上层 import `com.netease.*` |

**单一裁决原则**：所有外部事件（来电、导航、通知按键、耳机线控、蓝牙 A2DP）**先到照搬层**，由它决定暂停/降音量/恢复，再把最朴素的指令下发给 `PlayerController`（架构 §6.2）。上层不反向裁决。

:media-legacy/

```kotlin
// 定义在 :core-media（薄适配层，纯自研接口）；包名 com.example.cloudmusic.media，**永不变**
interface IMediaControl {
    /** 外部事件入口：由照搬层裁决后回调 PlayerController */
    fun onFocusChange(change: FocusChange)
    fun onMediaButton(key: MediaKey, action: MediaAction)
    fun bind(controller: PlayerControllerHandle)

    /** PlayerController 反向推送状态 */
    fun publishMetadata(track: Track, coverPath: String?)
    fun setPlaybackState(state: EngineState, positionMs: Long, durationMs: Long)
    fun setEnabled(enabled: Boolean)            // 切 DLNA 时禁用本机媒体会话

    // C-15（12 §44）：用户主动操作的状态回传；**默认空实现**，照搬层与测试替身零回归
    fun onPlaying() {}
    fun onManualPause() {}                       // 清「因焦点而暂停」标记（§12 T03）

    fun release()
}

enum class FocusChange { GAIN, GAIN_TRANSIENT, GAIN_TRANSIENT_MAY_DUCK,
                         LOSS, LOSS_TRANSIENT, LOSS_TRANSIENT_CAN_DUCK, OFF }
enum class MediaKey { PLAY, PAUSE, PLAY_PAUSE, NEXT, PREV, STOP, FAST_FORWARD, REWIND }
enum class MediaAction { DOWN, UP, LONG_PRESS, DOUBLE_CLICK }

/** PlayerController 暴露给照搬层的最小句柄；**定义在 `:core-media`**（与 IMediaControl 同域，避免舱依赖 :feature-player，2026-11-04 补注，`10 §2 R18`） */
interface PlayerControllerHandle {
    fun pauseFromFocus(); fun resumeFromFocus(); fun duck(volume: Float); fun unduck()
    fun play(); fun pause(); fun next(); fun prev(); fun seekRelative(deltaMs: Long)
}
```

> **★ 契约演进 C-15（2026-11-07，第三十五批 / `12 §44`）**：`PlaybackService` 的
> `MediaSession.Callback` 在 `onPlay` / `onPause` 把「用户主动播放 / 手动暂停」回传门面，
> 否则 `FocusPolicy` 无法区分「因焦点暂停」与「用户暂停」，§12 T03 在生产链路失效。
> 两方法带**默认空实现**：`:media-legacy` 与既有测试替身无需改动即可编译（零回归）；
> `InMemoryMediaControl` 覆写后驱动状态机，`FocusPolicy.onPlaying()` 同时清 `resumePending`，
> 避免 `LOSS_TRANSIENT` 后手动播放、再收到 `GAIN` 被重复 `resumeFromFocus()`。
> 长效守护见 `tools/check_source_contracts.py` 的 §43 / §44 检查段。

**Hilt 绑定**：`@Singleton` 提供 `MediaLegacyAdapter : IMediaControl`，只在 `PlaybackService` 中创建一次。

## 4. 焦点状态机（照搬语义）

```
        ┌────────────── 请求焦点成功 ──────────────┐
        ▼                                          │
   [有焦点 PLAYING]                          [空闲 IDLE]
        │                                          ▲
        ├ AUDIOFOCUS_LOSS            → 永久暂停 + 释放焦点
        ├ LOSS_TRANSIENT             → 暂停，标记「待恢复」
        ├ LOSS_TRANSIENT_CAN_DUCK   → duck(0.2~0.3)，保持播放
        ├ GAIN / GAIN_TRANSIENT     → unduck() / resumeFromFocus()
        └ AUDIOFOCUS_OFF / IGNORE   → 不响应（竞品常量语义）
```

| 事件 | 照搬层裁决 | 下发给 `PlayerControllerHandle` |
|---|---|---|
| `LOSS` | 停止并释放焦点 | `pauseFromFocus()`，**不自动恢复** |
| `LOSS_TRANSIENT` | 暂停，记录待恢复 | `pauseFromFocus()` |
| `GAIN` / `GAIN_TRANSIENT` | 恢复 | `unduck()` + `resumeFromFocus()` |
| `LOSS_TRANSIENT_CAN_DUCK` | 降音量 | `duck(0.25f)` |
| 短暂 duck 结束 | 恢复音量 | `unduck()` |
| 蓝牙 A2DP 断开 | 按 `LOSS` 处理（自动暂停，可关） | `pauseFromFocus()` |

> **不自动恢复的情况**：永久 `LOSS`、用户手动暂停、切到 DLNA 输出。恢复必须同时满足「之前是因焦点而暂停」+「重新获得 GAIN」。
>
> **★ T3 对齐补注（`12 §45`，2026-11-07）**：`FocusChange` 的三个 GAIN 变体
> （`GAIN` / `GAIN_TRANSIENT` / `GAIN_TRANSIENT_MAY_DUCK`）在 `FocusPolicy` 中**同走 `onGain`**，
> 但 Android 平台常量已**逐项映射、不再压平**（保留后续差异化裁决能力），
> 并由 `MediaControlContractTest` 的三变体用例守护。
> duck 链静态实测已通：`CAN_DUCK` → `HandleAdapter.duck(0.25f)` → `IMusicEngine.setVolume`
> → `EngineAdapter.setVolume` → `PlaybackEngine.setVolume`（native）；**真机听感待 G01**。
> `onPlay/onPause` 经 C-15 回传状态后，§12 T01~T03 在生产链路成立（`12 §44`）。

**`AudioFocusRequestCompat` 参数**（对齐竞品常量）：

```kotlin
val request = AudioFocusRequestCompat.Builder(AudioManagerCompat.AUDIOFOCUS_GAIN)
    .setAudioAttributes(AudioAttributesCompat.Builder()
        .setUsage(USAGE_MEDIA).setContentType(CONTENT_TYPE_MUSIC).build())
    .setOnAudioFocusChangeListener(::onFocusChange)
    .setWillPauseWhenDucked(false)     // 我们自己 duck，不让系统暂停
    .build()
```

## 5. 媒体按键分发

| 键 | 动作 | 目标 |
|---|---|---|
| `KEYCODE_MEDIA_PLAY_PAUSE` / `HEADSETHOOK` | 切换 | `play()/pause()` |
| `KEYCODE_MEDIA_NEXT` | 下一首 | `next()` |
| `KEYCODE_MEDIA_PREVIOUS` | 上一首 | `prev()`（播放 >3s 时按竞品语义可作「回到开头」，需以实际 dex 为准） |
| `KEYCODE_MEDIA_FAST_FORWARD` / `REWIND` | ±10s | `seekRelative(±10_000)` |
| 双击 / 长按 | 竞品语义（通常用于下一首/快进） | 由 `MediaAction` 传入，照搬层判定 |

> ⚠️ **targetSdk 35 适配点**：`MediaButtonEventReceiver` 是旧式 `BroadcastReceiver` 注册方式，在新系统上可能收不到按键。照搬时**保留它的分发语义**（连击判定、双击间隔），但把**入口**改挂到 `MediaSession.Callback.onMediaButtonEvent()`；Receiver 声明保留作为兼容兜底，不得两个入口重复处理同一次按键。

## 6. 通知栏 / 锁屏 / AVRCP

| 项 | 实现 |
|---|---|
| 通知渠道 | `NotificationChannel("playback", "播放控制", IMPORTANCE_LOW)`，minSdk 26 必须建渠道 |
| 权限 | `POST_NOTIFICATIONS`（API 33+）未授予时**仍可播放**，只是无通知（PRD §9） |
| 前台服务 | `PlaybackService` + `foregroundServiceType=mediaPlayback`，通知由照搬层样式驱动 |
| 锁屏封面 | `MediaMetadata` 的 `ALBUM_ART` / `ALBUM_ART_URI`，大图压缩到 512×512 |
| 元数据字段 | `METADATA_KEY_TITLE / ARTIST / ALBUM / DURATION / ALBUM_ART` |
| 播放状态 | `PlaybackState` 的 state + position + 支持动作集合（play/pause/next/prev/seek） |
| AVRCP | 由系统蓝牙栈读取上述会话，App 不直接连蓝牙 API（03-09） |
| 进度同步 | `PlayerController` 每 1s 或状态变化时调 `setPlaybackState`，避免锁屏进度停滞 |

**`setEnabled(false)`**：切到 DLNA 输出时禁用本机媒体会话与通知控件（手机变遥控器），回落本机时 `setEnabled(true)` 并重新 `publishMetadata`。切换时序见 03-08。

> `:media-legacy` 的 `res/`（通知图标/样式资源）同属第三方素材：每导出一项即按 `06 §4` 登记进 `docs/assets-mapping.csv`（`replaced=false`），发布前须全量 `replaced=true`（C4 检查，03-12 §3；2026-11-04 补注，`10 §2 R16`）。

## 9. 时序

### 9.1 来电 → 挂断恢复
```
系统 AUDIOFOCUS_LOSS_TRANSIENT
 → IMediaControl.onFocusChange(LOSS_TRANSIENT)
 → PlayerControllerHandle.pauseFromFocus()   // 标记「因焦点暂停」
 → setPlaybackState(PAUSED, pos, dur)
通话结束 AUDIOFOCUS_GAIN
 → resumeFromFocus() → engine.play() → setPlaybackState(PLAYING, ...)
```

### 9.2 导航播报（duck）
```
LOSS_TRANSIENT_CAN_DUCK → duck(0.25f) → engine.setVolume(0.25f)
GAIN → unduck() → engine.setVolume(1.0f)
```

### 9.3 耳机线控下一首
```
MediaSession.Callback.onMediaButtonEvent(KEYCODE_MEDIA_NEXT)
 → onMediaButton(NEXT, DOWN) → PlayerControllerHandle.next()
 → 03-06 切歌 → publishMetadata(新 Track) → 通知/锁屏/AVRCP 同步更新
```

### 9.4 切 DLNA
```
OutputRouter.setActive(DMR)
 → IMediaControl.setEnabled(false)   // 停本机通知控件
 → PlayerController 静音（03-08）
 → 手机 UI 变遥控器
```

## 10. 错误码

| 码 | 触发 | 处理 |
|---|---|---|
| `E_OUT_FOCUS_REQUEST_FAILED` | `requestAudioFocus` 返回 FAIL | 记 `failure_log`，仍允许播放（不阻断用户） |
| `E_OUT_SESSION_INIT` | MediaSession 创建失败 | 降级为「仅前台服务 + 无锁屏控制」，UI 提示 |

| `E_OUT_LEGACY_ABI` | 照搬层 JNI/类加载失败 | 阻断启动并提示（与 03-06 ABI 验收同规格） |

## 11. 边界条件清单

| # | 条件 | 期望行为 |
|---|---|---|
| B01 | 永久 LOSS 后重新 GAIN | **不**自动恢复（用户需手动播放） |
| B02 | 用户手动暂停后又收到 GAIN | 不恢复（恢复仅限「因焦点暂停」） |
| B03 | 连续多次 duck / unduck | 音量幂等，最终回到 1.0 |
| B04 | `POST_NOTIFICATIONS` 未授予 | 播放正常，仅无通知 |
| B05 | 切 DLNA 期间来电 | 本机会话已禁用，不重复暂停；DMR 侧由 03-08 处理 |
| B06 | 蓝牙断开同时来电 | 只暂停一次，状态不抖动 |
| B07 | 锁屏封面 > 5MB | 压缩到 512×512，超限回落占位 |
| B08 | 元数据为空 Track | 发布文件名兜底，不崩溃 |
| B09 | 旧式 Receiver 与 Session.Callback 同时收到按键 | 去重，只处理一次（§5） |
| B10 | 后台 2h | 前台服务持有会话，不被回收 |
| B11 | 照搬层某个剔除类被间接引用 | 空实现桩兜底，不拖入在线业务 |
| B12 | targetSdk 35 下 `MediaButtonEventReceiver` 失效 | 以 Session.Callback 为主入口，行为不变 |
