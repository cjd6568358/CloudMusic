## 2. UI 技术栈与双框架共存

| 范围 | 技术 | 说明 |
|---|---|---|
| 除播放页外的全部页面 | **Jetpack Compose + Material3 + Coil** | 自研 |
| 播放页 | **竞品 View 体系**（Activity + XML layout + 自定义 View + anim） | 整页照搬 |
| 导航 | Compose Navigation；播放页经 `AndroidView` 或独立 Activity 跳转 | 见 §6 |
| 主题 | 深色优先 + 跟随系统；主色 `#FF3A3A` / `#FF2C55` | PRD §13 #9 |

**共存规则**：

```
:app (Compose)
  └─ PlayerRoute → 两种接入方式，二选一（建议 A）：
     A. 独立 Activity：startActivity(PlayerActivity) —— 照搬页保持完整生命周期，最省事
     B. AndroidView(factory = { LegacyPlayerView(ctx) }) —— 若日后要把播放页嵌进 Compose 导航
  └─ 状态桥：PlayerStateBridge（把 StateFlow 转成照搬页能读的回调/LiveData）
```

- **建议 A**（独立 Activity）：竞品 `PlayerActivity` 有自己的生命周期、动画、资源引用，硬塞进 `AndroidView` 容易踩 View 测量/状态保存的坑。
- `:ui-legacy` 是**独立 Gradle module**，只放照搬的 layout / drawable / anim / 自定义 View 代码，避免污染 `:app` 的 R 文件。
- 两个 module 之间只通过 `PlayerStateBridge` 通信，`:ui-legacy` 不 import 任何自研业务类。

## 3. 播放页照搬：资源 ID 反查流程（★必须按此执行）

APK 实测：`res/anim/` 下 **2,227 个 XML**（public.xml 收录 2,232 条 anim，`06 §1`）、`drawable-xxhdpi` 数千个，**文件名全部混淆**（`a.xml`、`a0.xml`、`a.webp`、`b21.xml`），`colors.xml` 里 2,561 个颜色名也是 `a/aa/b21`。**无法按文件名挑素材**。

### 3.1 反查步骤

> **2026-11-05 P2 实证补充（`14`）**：`android:tag` 保留了原始 layout 语义名（1,754 个），可直接建映射，无需只靠 ① 的资源 ID；`06 §3` 九步的静态部分（①~⑥）已由 `tools/player_resource_audit.py` 完成，产出 163 项资源闭包。
> **本表「旋转周期 12s」是示例值**：实测 `res/anim*` 里 40 个无限循环 rotate 候选的 `duration` 从 1000 到 21600000，**没有 12000**，`pivotX/Y` 全为 50%、`toDegrees` 为 ±360。具体是哪个 anim 需 jadx / 真机确认，**不得按示例值推定**；视觉参数仍以下方表格要求的「反查到的 XML 为准」。

```
① jadx / baksmali 反编译 PlayerActivity 及其自定义唱片 View
   → 找到所有资源引用常量，如 const v0, 0x7f010002 / 0x7f0400a1
② 打开 analysis/decoded/res/values/public.xml
   → 形如 <public type="anim" name="a02" id="0x7f010002"/>
   → 按 id 反查得到混淆名
③ 从 APK 导出该资源文件（anim XML / drawable / layout / color）
④ 连同 layout 里引用的其他资源递归反查，直到闭包完整
⑤ 建立映射表（§3.2），把混淆名 → 语义名登记
⑥ 把资源与 View 代码放进 :ui-legacy，跑一次编译验证引用齐全
```

> 递归闭包是重点：一个播放页 layout 会引用 drawable、dimen、color、anim、style，每个又要继续反查。漏一个就是运行时 `Resources$NotFoundException`。

### 3.2 映射表（`docs/assets-mapping.csv`，03-12 校验）

```csv
legacy_name,type,semantic_name,used_by,notes
a02.xml,anim,player_disc_rotate,PlayerActivity,旋转周期 12s
a03.xml,anim,player_needle_down,CustomDiscView,唱针落下
b21.xml,drawable,player_disc_mask,layout_player,黑胶底图
...
```

字段：`legacy_name` / `type` / `semantic_name` / `used_by` / `notes`（视觉度量参数）。

### 3.3 视觉度量（照搬，不重新设计）

| 项 | 来源 | 说明 |
|---|---|---|
| 唱片直径 / 边距 | layout XML 的 dimen | 直接从反查到的 dimen 取值 |
| 唱针 pivot / 旋转角度 | anim XML 的 `pivotX` / `fromDegrees` / `toDegrees` | 暂停抬起、播放落下 |
| 旋转周期 | anim 的 `duration` + `repeatCount="infinite"` | 播放匀速、暂停停转 |
| 插值器 | `interpolator` 引用 | 照搬，不替换成 Material 动效 |
| 动画时长 | `@android:integer/config_mediumAnimTime` 等 | 保持原值 |
| 主色 / 文字色 | `colors.xml` 对应 id | `#FF3A3A` / `#FF2C55` |

> **禁止**用 Compose 的 `animateFloatAsState` 去"近似"这些参数——决策 ① 要求照搬，参数以反查到的 XML 为准。

> ⚠️ **targetSdk 35 适配点（2026-11-04 补注，`10 §2 R17`）**：Android 15 起强制 edge-to-edge，照搬的 View 布局会被顶进系统栏。适配方式 = 外层加 insets 处理（`ViewCompat.setOnApplyWindowInsetsListener` 补安全区 padding），**不修改**反查到的视觉参数（dimen/margin 原值保留）。

### 3.4 资源命名冲突处理

照搬资源名（`a.xml`、`a0.webp`）太通用，与 `:app` 或其他库合并时可能撞名。两种方案：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 导出时统一加前缀 `legacy_`，批量改写 layout / 代码里的 `R.anim.a02` → `R.anim.legacy_a02` | 需要一次性脚本，但一劳永逸 |
| B | 保持原名，靠 `:ui-legacy` 独立 namespace 隔离 | 仍可能与第三方库资源撞名，且 R8 资源压缩易误删 |

选 A 时，改写脚本与映射表一起纳入 03-12 的构建前置检查。

@Composable fun CloudMusicTheme(

## 6. 播放页状态桥（照搬 View ↔ StateFlow）

`PlayerStateBridge` 是两层之间**唯一通道**：

```kotlin
class PlayerStateBridge @Inject constructor(
    private val controller: PlayerController,
) {
    /** 供 :ui-legacy 订阅（转成 LiveData / 回调，避免照搬层依赖 Flow） */
    val track: StateFlow<Track?>            // → 标题/艺人/封面
    val state: StateFlow<PlayerState>       // → 唱片旋转 / 唱针起落 / 按钮态
    val positionMs: StateFlow<Long>         // → 进度条（每 1s）
    val playMode: StateFlow<PlayMode>       // → 模式图标
    val queueCount: StateFlow<Int>

    /** 照搬 View 的用户操作回调 */
    fun onPlayPause(); fun onNext(); fun onPrev()
    fun onSeek(ms: Long); fun onModeToggle(); fun onFavorite()
    fun onOpenQueue(); fun onOpenOutput()
}
```

**映射表**（照搬页控件 → 桥）：

| 照搬页控件 | 读/写 |
|---|---|
| 唱片 View 旋转 / 唱针 | 读 `state`：PLAYING→转+针落；PAUSED/IDLE→停+针抬 |
| 播放/暂停按钮 | 读 `state`，写 `onPlayPause()` |
| 进度条 | 读 `positionMs` / `durationMs`，写 `onSeek()` |
| 上一首/下一首 | 写 `onNext()` / `onPrev()` |
| 播放模式图标 | 读 `playMode`，写 `onModeToggle()` |
| 收藏 | 读 `Track` 的收藏态，写 `onFavorite()` |
| 队列/输出入口 | 写 `onOpenQueue()` / `onOpenOutput()` |

> 03-06 §17 遗留项「播放页整页照搬后与 `PlayerController` 的绑定方式」在此闭环。照搬页**不得**直接持有 `PlayerController` 或 `IMusicEngine`。

## 7. 输出设备弹窗（对应 03-08 §16）

Compose 实现，读 `OutputRouter.state: StateFlow<OutputDeviceState>`：

| 区块 | 内容 |
|---|---|
| 本机 | 当前 `ActiveOutput=LOCAL` 时高亮；显示「本机扬声器」+ 蓝牙设备名（`BluetoothInfo.name`） |
| DLNA 设备列表 | SSDP 发现项 + 手动项，各自标注来源 `[发现]` / `[手动]`；显示 `friendlyName` / `manufacturer` |
| 手动输入表单 | IP/域名、端口（可空）、完整 descriptionUrl（可空）、备注名；提交后走 `ManualDmrSpec` 探测 |
| 历史 | `manualDmrHistory`（03-05 DataStore），点选即用 |
| 控制 | 投屏中显示 DMR 回传进度、暂停/跳转/音量，及「回到本机」 |

- 错误展示直接用 `E_OUT_*` 的上游消息（03-08 §11），不显示笼统「连接失败」。
- 纯直链投屏时弹窗可显示「不经手机转发」提示（来自 `CastUri.viaProxy`）。

## 11. 明确禁止事项

1. 禁止用 Compose Canvas 重写唱片动画（决策 ①）。
2. 禁止修改照搬 anim 的 `duration` / `pivotX` / `interpolator` 等视觉参数。
3. 禁止 `:ui-legacy` import 自研业务类或 `IMusicEngine`。
4. 禁止 UI 层直接调 `Driver` / Room / OkHttp（一律经 Repository 与 StateFlow）。
5. 禁止按文件名猜测混淆资源（必须走 §3.1 的 ID 反查）。
6. 禁止在发布前保留任何竞品品牌图标/字体/文案/应用名。
7. 禁止新增启动页广告、信息流、评论区、动态主题商店（PRD §7）。
8. 禁止把蓝牙列为与本机/DLNA 并列的可选输出（03-09 §3）。
