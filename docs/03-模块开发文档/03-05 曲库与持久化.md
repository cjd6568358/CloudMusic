## 2. 存储分布总表

| 数据 | 存储 | 理由 |
|---|---|---|
| `tracks` / `playlists` / `favorites` / `play_history` / `scan_snapshot` / `queue_items` / `playback_state` / `failure_log` | **Room（SQLite）** | 关系查询、批量事务、迁移工具成熟 |
| `Storage` 列表、`Addition`（含 WebDAV 账号密码）、设置项 | **DataStore(Proto) 明文** | 决策 ④：个人作品，不引入 Keystore/加密；避开国产 ROM 上 `EncryptedSharedPreferences` 兼容问题 |
| 封面缓存 | `cacheDir/covers/{trackId}.webp` | 不入库，DB 只存路径 |
| 引擎指纹 | `assets/ENGINE-FINGERPRINT` | 随舱冻结（03-06） |

> ⚠️ **Room 与 DataStore 之间不做物理外键**：`Track.sourceRef.storageId` 逻辑指向 DataStore 里的 `Storage.id`，跨存储无法建 FK。删除 Storage 时由 `StorageRepository` 显式调 `TrackRepository.markOrphan()`，不依赖级联。

## 3. Room Schema（V0.1 全表）

```sql
-- 3.1 曲库主表
CREATE TABLE tracks (
    id                TEXT PRIMARY KEY,          -- TrackId.value
    title             TEXT NOT NULL,
    artist            TEXT NOT NULL,
    album             TEXT NOT NULL,
    duration_ms       INTEGER NOT NULL DEFAULT 0,
    track_no          INTEGER NOT NULL DEFAULT 0,
    year              INTEGER NOT NULL DEFAULT 0,
    sample_rate       INTEGER NOT NULL DEFAULT 0,
    bit_depth         INTEGER NOT NULL DEFAULT 0,
    storage_id        TEXT NOT NULL,             -- 逻辑外键 → DataStore Storage.id
    source_path       TEXT NOT NULL,
    source_url        TEXT,                      -- strm / 播放列表 URL 条目
    source_type       TEXT NOT NULL,             -- LOCAL/WEBDAV/STRM/PLAYLIST/...
    cover_ref         TEXT,
    tag_completeness  REAL NOT NULL DEFAULT 0,
    availability      TEXT NOT NULL DEFAULT 'OK',
    added_at          INTEGER NOT NULL,
    updated_at        INTEGER NOT NULL
);
CREATE INDEX idx_tracks_title   ON tracks(title);
CREATE INDEX idx_tracks_artist  ON tracks(artist);
CREATE INDEX idx_tracks_album   ON tracks(album);
CREATE INDEX idx_tracks_storage ON tracks(storage_id);
CREATE INDEX idx_tracks_avail   ON tracks(availability);
-- FTS 全文检索（标题/艺人/专辑）
CREATE VIRTUAL TABLE tracks_fts USING fts4(content='tracks', title, artist, album);

-- 3.2 歌单（跨来源混合）
CREATE TABLE playlists (
    id         TEXT PRIMARY KEY,
    name       TEXT NOT NULL,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
CREATE TABLE playlist_tracks (
    playlist_id TEXT NOT NULL,
    position    INTEGER NOT NULL,
    track_id    TEXT NOT NULL,
    added_at    INTEGER NOT NULL,
    PRIMARY KEY (playlist_id, position)
);
CREATE INDEX idx_pt_track ON playlist_tracks(track_id);

-- 3.3 收藏 / 播放记录
CREATE TABLE favorites (
    track_id   TEXT PRIMARY KEY,
    added_at   INTEGER NOT NULL
);
CREATE TABLE play_history (
    track_id   TEXT PRIMARY KEY,
    last_played INTEGER NOT NULL,
    play_count  INTEGER NOT NULL DEFAULT 1
);

-- 3.4 失败记录（03-06 §13 引用）
CREATE TABLE failure_log (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    track_id   TEXT NOT NULL,
    code       TEXT NOT NULL,
    detail     TEXT,
    happened_at INTEGER NOT NULL
);
CREATE INDEX idx_failure_time ON failure_log(happened_at);
```

**已在其他文档定义、本文登记所有权**：

| 表 | 定义处 | 用途 |
|---|---|---|
| `scan_snapshot` | 03-04 §8 | `(storage_id, path, size, modified, kind, scanned_at)` |
| `queue_items` | 03-06 §8.1 | 播放队列业务真相源 |

## 5. Repository 接口

```kotlin
interface TrackRepository {
    fun observeAll(): Flow<List<Track>>
    fun search(query: String): Flow<List<Track>>          // FTS + LIKE 兜底
    fun byAlbum(album: String): Flow<List<Track>>
    fun byArtist(artist: String): Flow<List<Track>>
    fun byFolder(prefix: String): Flow<List<Track>>
    suspend fun get(id: TrackId): Track?
    suspend fun upsertBatch(tracks: List<Track>)          // ★每 500 条一个事务
    suspend fun markAvailability(id: TrackId, a: Availability)
    suspend fun markOrphan(storageId: String)             // 删除 Storage 时调用
    suspend fun count(): Int
}

interface PlaylistRepository {
    fun observePlaylists(): Flow<List<Playlist>>
    fun observeTracks(playlistId: String): Flow<List<Track>>
    suspend fun create(name: String): String
    suspend fun rename(id: String, name: String)
    suspend fun delete(id: String)
    suspend fun addTracks(id: String, trackIds: List<TrackId>)   // 跨来源混合
    suspend fun move(id: String, from: Int, to: Int)
    suspend fun remove(id: String, position: Int)
}

interface FavoriteRepository { fun observe(): Flow<Set<TrackId>>; suspend fun toggle(id: TrackId) }
interface HistoryRepository  { suspend fun record(id: TrackId); fun observe(): Flow<List<Track>> }
interface StorageRepository {
    fun observe(): Flow<List<Storage>>
    suspend fun add(type: String, additionJson: String): Storage   // 生成稳定 UUID
    suspend fun update(s: Storage)
    suspend fun remove(id: String)                                 // 同时 markOrphan
    suspend fun setError(id: String, msg: String)
}
```

**所有返回集合的方法用 `Flow`**：Room / DataStore 变更自动推给 UI，无需手动刷新（架构 §10 单向数据流）。

> **实现期补充 C-03（2026-11-05，见 `12 §13`）**：本文 §5 用到的 `Playlist` / `PlaylistMember` 与 §3 的 `FailureRecord` / `TrackEntity` 在 `:core-model` 未定义，按本文表结构就近定义在 `:core-storage`（`LibraryModels.kt`），**不改 `:core-model` 契约、不改 Repository 签名**；`TrackEntity` 的枚举一律按字符串名存取（§10 / §14 #7）。

## 6. 批量 upsert 与事务（性能关键）

```kotlin
@Transaction
override suspend fun upsertBatch(tracks: List<Track>) {
    tracks.chunked(500).forEach { batch ->
        val entities = batch.map(TrackEntity::from)
        trackDao.upsertAll(entities)          // @Upsert，按 id 冲突替换
        ftsDao.sync(batch)                    // FTS 外部内容表同步
    }
}
```

| 规则 | 说明 |
|---|---|
| 批大小 | 500（03-04 阶段 A 与阶段 B 共用） |
| 冲突策略 | `@Upsert` 按主键 `id` 覆盖；**保留** `added_at`，更新 `updated_at` |
| 不覆盖字段 | `availability`、`favorites`、`play_count` 由各自 Repository 维护，upsert 不得重置 |
| FTS 同步 | 用 `content='tracks'` 外部内容表，需显式维护触发器或在同一事务里同步 |
| 阶段 B | 单条补齐元数据也走同一个 `upsertBatch(listOf(track))`，不写第二套逻辑 |

> **实现期澄清 C-04（2026-11-05，见 `12 §13`）**：§7 硬规则 / T10「文件恢复出现自动置回 `OK`」，与上表「upsert 不覆盖 `availability`」在 Room 的 `@Upsert` 全列覆盖下会直接冲突（03-04 阶段 A/B 生成的 `Track` 默认都是 `OK`）。处置：`upsertBatch` **严格保留**既有状态，连阶段 B 的单条元数据补齐也不得抹掉播放失败标记的 `LINK_EXPIRED`；恢复改走 `:core-storage/ScanReconciler.upsertFromScan` 显式通道 —— 先 `upsertBatch`，再对**本次确实扫到的**曲目按扫描结果调用 `markAvailability`。Android 侧组合时把 03-04 的 `TrackSink.upsertBatch / markUnavailable` 委托给该通道；Room 实现可把逐条更新优化为单事务批量 `UPDATE`，语义不变。`upsertBatch` 的公开签名不变。

## 7. `Availability` 状态机

```
                  恢复出现 / 重扫成功
        ┌──────────────────────────────┐
        ▼                              │
       OK  ──文件消失/Storage失联──▶ UNREACHABLE
        │  ──直链 403/超时──▶ LINK_EXPIRED
        │  ──非 http scheme──▶ UNSUPPORTED_SCHEME
        └──────── 以上三者 ────────────┘
```

| 状态 | UI | 触发来源 | 恢复 |
|---|---|---|---|
| `OK` | 正常 | 初始 / 重扫成功 | — |
| `UNREACHABLE` | 灰显 | 03-04 快照缺失 / 03-02 连不上 / `Storage.disabled` | 文件重新出现 / 网络恢复 / 重扫 |
| `LINK_EXPIRED` | 灰显 + 「链接失效」标 | 03-06 播放直链 403/超时 | 重新扫描 / 手动重试 |
| `UNSUPPORTED_SCHEME` | 灰显 + 可筛选 | 03-03 strm scheme 非 http | 编辑 strm 后重扫 |

**硬规则**：任何状态下**都不删除 `Track` 行**（PRD §5.3）。恢复时只把 `availability` 置回 `OK`，收藏、播放记录、歌单成员关系全部保留。

## 8. 搜索、排序与去重

| 能力 | 实现 |
|---|---|
| 搜索 | `tracks_fts` MATCH；短查询（<2 字符）或 FTS 无结果时回落 `LIKE %q%`；跨来源结果合并 |
| 排序 | 标题 / 艺人 / 专辑 / 添加时间 / 时长；中文按 `Collator(Locale.CHINA)` 排序，不用二进制序 |
| 文件夹视图 | `source_path` 前缀分组，路径来自 03-01 规范化结果 |
| 重复曲目 | **允许共存**（PRD §13 #14）：不同 `storageId`/路径即不同 ID |
| 「合并重复项」开关 | **纯展示层**：按 `(title, artist, durationMs±2s)` 分组折叠，不改数据、不合并 ID |

> 开关状态存 `AppSettings`，只影响 UI 的 `Flow` 变换，Repository 层不感知。

## 9. 跨来源混合

歌单 / 队列 / 搜索结果里的 `Track` 可能来自 Local、WebDAV、strm、播放列表，Repository **不做来源区分**：

- `playlist_tracks.track_id` 只是 `tracks.id` 的逻辑引用，无来源字段。
- 03-06 队列恢复时按 `Track.sourceRef` 重建 `Link`，不缓存 `Link` 对象（03-06 §16 禁止事项）。
- 删除某个 `Storage`：`markOrphan(storageId)` 把相关 `Track` 标 `UNREACHABLE`，**歌单成员关系保留**（用户重新挂回同一目录后可恢复）。

## 10. 迁移策略

| 版本 | 变更 | Migration |
|---|---|---|
| 1 | 初始全表 | — |
| 2+ | 新增列一律 `ALTER TABLE ... ADD COLUMN ... DEFAULT`，禁止破坏性重建 | `Migration(1,2){ ... }` |

- 每个 Migration 必须写**单元测试**（`MigrationTestHelper`）：造 v1 数据 → 跑迁移 → 校验数据不丢。
- `Availability` / `SourceType` 在 DB 里存**字符串枚举名**而非序号：新增枚举值时不需要迁移。
- `additionRaw` 在 DataStore 里是 JSON 字符串，新增字段由 03-02 的 `firstStr()` 兼容读取，无 schema 迁移。

## 11. 错误码

| 码 | 触发 | 处理 |
|---|---|---|
| `E_DB_MIGRATION` | Migration 失败 | 阻止启动，提示用户清除数据或升级 App（不静默 fallbackToDestructiveMigration） |
| `E_DB_FULL` | 磁盘写满 / SQLite_FULL | 停止扫描，UI 提示释放空间，已入库数据保留 |
| `E_DB_CONSTRAINT` | 唯一键冲突（TrackId 碰撞） | 03-04 追加后缀重试；仍失败记日志并跳过该文件 |
| `E_DS_STORAGE_MISSING` | `sourceRef.storageId` 在 DataStore 找不到 | 标 `UNREACHABLE`，不崩溃 |

> **禁止** `fallbackToDestructiveMigration()`：曲库是用户资产，静默清库不可接受。

## 14. 明确禁止事项

1. 禁止 `fallbackToDestructiveMigration()`。
2. 禁止把凭据写进 Room、日志、崩溃上报（凭据只在 DataStore 明文段）。
3. 禁止在 `upsertBatch` 里重置 `availability` / 收藏 / 播放次数。
4. 禁止缓存 `Link` 对象（只存 `SourceRef`）。
5. 禁止对「本次没扫到」或「播放失败」的曲目执行 `DELETE`。
6. 禁止逐条 Room insert（必须 500 条批量事务）。
7. 禁止用序号存枚举（用枚举名字符串）。
8. 禁止在 Repository 里做来源判断（跨来源必须透明）。
