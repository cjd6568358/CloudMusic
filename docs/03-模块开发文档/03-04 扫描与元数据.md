## 1. 职责与范围

| 做 | 不做 |
|---|---|

## 3. `ByteRangeCapability`（★回补 03-01 契约）

扫描网络音源时不能下载整文件，只需读头部若干 KB 做标签解析。但 03-01 的 `Driver` 只暴露 `list/get/link`，而 `link()` 返回的是**完整播放流**，不适合小范围读。故新增一个**可选能力接口**（不改动 `Driver` 基本契约）：

```kotlin
/** 定义在 :datasource-api；Local / WebDAV / SFTP / FTP 实现，Strm / Playlist 不需要 */
interface ByteRangeCapability {
    /** 从 offset 读最多 length 字节；越界返回实际可读长度；失败抛 CloudMusicError */
    suspend fun readBytes(file: Obj, offset: Long, length: Int): ByteArray
}
```

| 驱动 | 实现 |
|---|---|
| Local | `FileInputStream.channel.position(offset)` |
| WebDAV | 带当前 AuthMode 鉴权头的 `Range: bytes={offset}-{offset+length-1}` GET |
| SFTP / FTP（V0.2） | `Open()` / `RetrFrom(offset)` 读前 N 字节后关闭 |

> 03-02 的 `DirectLinkCapability` 与本节 `ByteRangeCapability` 都是**可选能力**：`ScanCoordinator` / `CastUriResolver` 用 `as?` 探测，未实现的驱动走降级路径，**不强制所有驱动实现**。已在 03-01 §2 / §5.1 / §13 回补。

## 4. 扫描触发与类型

| 触发 | 类型 | 行为 |
|---|---|---|
| 首次添加 Storage | 全量 | 递归全部目录，解析元数据 |
| 手动「重新扫描」 | 全量（可指定 Storage） | 强制 `refresh=true`，绕过缓存 |
| App 启动 | 轻量增量 | 只比较根目录与快照差异，≤10s |
| 前台下拉刷新 | 增量 | 同上，UI 显示进度条 |
| 网络恢复 / 手动「重试失败项」 | 定向增量 | 只重扫 `Availability != OK` 的条目 |

```kotlin
class ScanCoordinator @Inject constructor(
    private val storageRepo: StorageRepository,
    private val driverRegistry: DriverRegistry,
    private val trackRepo: TrackRepository,
    private val snapshot: ScanSnapshotStore,
    private val tagReader: TagReader,
    private val coverResolver: CoverResolver,
) {
    fun scan(request: ScanRequest): Flow<ScanProgress>
    fun cancel(storageId: String? = null)          // null = 取消全部
}
```

`ScanProgress(storageId, scanned, total, currentPath, errors: List<ScanError>, phase: FULL|INCREMENTAL|METADATA)`。

## 5. 扫描主流程

```
scan(request)
 ├ storageRepo.active() → List<Storage>
 ├ for each Storage (并发受 Semaphore(4) 限制):
 │   ├ driver = DriverRegistry.get(storage.id) ?: init/reconnect
 │   ├ walk(driver, root, depth=0, visited):
 │   │   ├ driver.list(dir, refresh) → List<Obj>
 │   │   ├ 过滤：排除规则（§9）
 │   │   ├ 目录 → 递归（跳过 visited、跳过 .nomedia 子树）
 │   │   └ 文件 → 分类：
 │   │        ├ .strm        → StrmDriver 解析 → 候选曲目
 │   │        ├ .m3u/.m3u8/.pls → PlaylistDriver 展开 → 多个候选
 │   │        └ 音频白名单  → 候选曲目
 │   ├ 增量判定：snapshot.compare(size, modified) → 只处理新增/变更
 │   ├ TrackFactory.build(candidate) → Track
 │   └ trackRepo.upsertBatch(tracks)   // 每 500 条一个 Room 事务
 └ 汇总：缺失项标 UNREACHABLE（不删除）、失败项汇总、更新 snapshot
```

**白名单**（PRD §5.4）：`mp3 / flac / wav / m4a / aac / ogg / opus / wma` + `.strm` + `.m3u/.m3u8/.pls`。
`ape / dsf / dff / aiff / wv / tak / cue` 归 V0.2~V1.0。**扩展名只作初筛，格式探测以文件内容为准**（`TagReader.probe()` 读 magic bytes）。

> **内联展开口径（2026-11-04 复核澄清，`10 §2 R5`）**：走查**任意 Storage** 时遇到的 `.strm` / `.m3u/.m3u8/.pls`，由扫描器**直接调用 03-03 的共享解析函数**（`parseStrm` / 播放列表解析器）内联展开，不要求实例化 `StrmDriver` / `PlaylistDriver`；两个驱动挂载仅服务于 `paths` 映射 / autoFlatten / 跨挂载虚拟目录等场景。同一底层文件若同时被内联展开与驱动挂载摄入，会产生两个不同 `TrackId` 的条目——按 PRD §13 #14 **允许共存**，UI「合并重复项」可折叠；V0.1 不做跨路径去重。

## 6. 元数据解析

### 6.1 `TagReader` 接口

```kotlin
interface TagReader {
    /** 只读取头部/尾部必要字节，返回原始标签；失败返回 EMPTY，不抛异常阻断扫描 */
    suspend fun read(candidate: Candidate): RawTags
    fun probe(head: ByteArray): AudioFormat?      // magic bytes 判定真实格式
}

data class RawTags(
    val title: String? = null, val artist: String? = null, val album: String? = null,
    val trackNo: Int? = null, val year: Int? = null, val genre: String? = null,
    val durationMs: Long? = null, val sampleRate: Int? = null, val bitDepth: Int? = null,
    val embeddedCover: ByteArray? = null,
    val completeness: Float = 0f,
)
```

### 6.2 实现选型（已定案：不照搬 native）

> **实测纠错（2026-11-04）**：对 `analysis/decoded/lib/arm64-v8a/` 的 167 个 so 做 ELF 解析后发现，本文初稿误把 **`libscannative.so` 当成音乐扫描库**——它的 JNI 符号全部是 `Java_com_huawei_hms_scankit_util_OpencvJNI_*`，实为**华为 HMS ScanKit 扫码/二维码库**，与音乐无关。详见 `05-Native库实测分析.md §3`。

| 候选库 | 实测结果 | 结论 |
|---|---|---|
| `libscannative.so`(2.6M) | JNI 符号 7 个，全属 `com.huawei.hms.scankit.util.OpencvJNI`；DT_NEEDED 仅 `libz/liblog/libm/libdl/libc` | ❌ **排除**：扫码库 |
| `liblive_disk_scanner.so`(565K) | 含 `DiskScannerDelegate` / `File system scan failed` 字符串，**JNI 导出 0** | ❌ 排除：纯 C++ 内部库，无 Java 入口 |
| `libnecmMediaInfo.so`(358K) | DT_NEEDED 依赖 `libnecmMediaCommon.so`，**JNI 导出 0** | ❌ 排除：纯 C++ 内部库 |
| `libnecmMediaCommon.so`(2.0M) | 含 `PARSE_TAGGING` / `GetMPEGAudioFrameSize`，**JNI 导出 0** | ❌ 排除：无 Java 入口，闭包大 |
| `libfpGenerate.so` | 含 ID3v2.3 帧解析字符串 | ❌ 排除：音频指纹，PRD §8 不做 |
| `libffmpeg.so`(6.5M) | 含 Vorbis/FLAC demuxer，无 JNI 导出；已被播放内核舱依赖 | ❌ 排除：不重复引入 |

**定案**：标签解析**一律采用 `JAudioTaggerTagReader`（LGPL）+ Android `MediaMetadataRetriever`**；目录递归、增量、封面优先级等扫描逻辑全部自研。理由：

1. 竞品里与元数据相关的 native 库**均无 JNI 导出**（纯 C++ 内部库），照搬后无法从 Java 层直接调用，需自写 JNI 桥并拖入庞大依赖闭包——既不「避免 bug」，也无收益。
2. 用户 A1「优先复制 so」针对的是**播放内核**（有明确的 `playerengine.*` JNI 入口）；扫描层不存在可匹配场景，属「无匹配场景」，照搬原则不适用（架构 §0 A1）。
3. `TagReader` 接口保持不变；未来若取得可用的竞品 Java 层封装，只需新增一个实现类并改 Hilt 绑定，上层零改动。

> 本定案取代初稿的「先照搬再兜底」两阶段方案；`03-12 §4` 中「`libscannative.so` 单独 ABI 验收」相应取消。

### 6.3 支持的标签类型

| 格式 | 标签 |
|---|---|
| MP3 | ID3v1（尾部 128B）/ ID3v2.2/2.3/2.4（头部，含 APIC 封面） |
| FLAC / OGG / Opus | Vorbis Comment + `METADATA_BLOCK_PICTURE` |
| M4A / AAC | MP4 atoms（`©nam` / `©ART` / `©alb` / `covr` / `trkn`） |
| APE / WV（V0.2） | APE tag |
| WAV | RIFF INFO / ID3 chunk |

**只读取必要范围**：ID3v2 头部（前 64KB，含 APIC 可能更大时按需扩到 512KB）、ID3v1 尾部 128B、FLAC 元数据块头部；**禁止下载整个文件**。网络音源经 `ByteRangeCapability.readBytes()` 完成。

### 6.4 封面优先级（`CoverResolver`）

```
1. 内嵌标签封面（APIC / covr / METADATA_BLOCK_PICTURE）
2. 同目录 cover.jpg / cover.png / folder.jpg / front.jpg（大小写不敏感）
3. 占位图（应用内资源）
```

- 封面写入 `cacheDir/covers/{trackId}.webp`（统一压缩到 512×512，质量 80），DB 只存路径。
- 网络音源的同目录封面经 `ByteRangeCapability` 取；失败直接回落占位图，不重试超过 1 次。
- **不联网刮削**（V0.1）。

### 6.5 文件名兜底（`NameParser`）

标签缺失时按以下顺序补全 `Track`：

```
title  ← 播放列表 #EXTINF / pls Title
       ← 文件名 "艺人 - 标题" 拆分
       ← 文件名去扩展名
artist ← "艺人 - 标题" 左半
       ← 父目录名（若形如 "艺人 - 专辑" 取左半）
       ← 未知
album  ← 父目录名 / 标签
```

`tagCompleteness` 计算：标签齐全 1.0 / 部分 0.5 / 仅文件名 0.2 / strm 与播放列表条目起始 0.2。

## 7. `TrackFactory` 与 ID 稳定性

```kotlin
suspend fun build(c: Candidate): Track {
    val raw = tagReader.read(c)                    // 失败返回 EMPTY，不中断
    val cover = coverResolver.resolve(c, raw.embeddedCover)
    val fallback = NameParser.parse(c.obj.name, c.parentDirName, c.hint)
    return Track(
        id = TrackId.of(c.storageId, c.obj.path),  // 03-01 §7：不含 host/凭据
        title = raw.title ?: fallback.title,
        artist = raw.artist ?: fallback.artist,
        album = raw.album ?: fallback.album,
        trackNo = raw.trackNo ?: 0, year = raw.year ?: 0,
        durationMs = raw.durationMs ?: c.hint?.durationMs ?: 0,
        sampleRate = raw.sampleRate ?: 0, bitDepth = raw.bitDepth ?: 0,
        sourceRef = c.toSourceRef(), sourceType = c.sourceType,
        coverRef = cover, tagCompleteness = max(raw.completeness, fallback.completeness),
        availability = Availability.OK,
    )
}
```

> **`TrackId` 不含 host / 端口 / 账号**：WebDAV 换地址只改 `Addition`，`Storage.id` 不变 → ID 不变 → 收藏与播放记录保留（PRD §5.3）。

## 8. 增量扫描

```sql
CREATE TABLE scan_snapshot (
    storage_id   TEXT NOT NULL,
    path         TEXT NOT NULL,
    size         INTEGER NOT NULL,
    modified     INTEGER NOT NULL,
    kind         TEXT NOT NULL,      -- AUDIO / STRM / PLAYLIST
    scanned_at   INTEGER NOT NULL,
    PRIMARY KEY (storage_id, path)
);
```

| 情况 | 处理 |
|---|---|
| `(size, modified)` 与快照一致 | 跳过（不读标签、不写 DB） |
| 新增 / 变更 | 重新解析并 upsert |
| 快照有、本次没扫到 | 标 `Availability.UNREACHABLE`，**不删除** |
| 文件恢复出现 | 自动置回 `OK` |
| `Storage.modified` 变更（配置改了） | 该 Storage 强制全量 |

WebDAV 的 `modified` 取 `getlastmodified`；服务器不返回该字段时退化为 `size` 比较，仍不返回则每次全量（记录到扫描报告）。

## 10. 性能达标策略（PRD §10 #2：冷扫 ≤60s / 增量 ≤10s）

7,500 首里 2,000 首在 WebDAV、500 首是 strm，逐个做网络标签解析必然超时。采用**两阶段扫描**：

```
阶段 A（快速入库，目标 ≤ 15s）
  ├ 只列目录 + 文件名兜底，生成 Track 骨架
  ├ 网络音源 / strm 一律不读标签（tagCompleteness=0.2）
  └ 立即 upsert → UI 马上能看到曲库

阶段 B（后台补元数据，不阻塞用户）
  ├ 低优先级协程 + Semaphore(2)，逐条经 ByteRangeCapability 读头部
  ├ 可配置「仅 WiFi 补元数据」；移动网络下暂停
  ├ 封面同样在阶段 B 生成
  └ 每条完成后单独 upsert，UI 实时刷新
```

其余硬性优化：

1. **批量事务**：Room upsert 每 500 条一个事务，禁止逐条 `insert`。
2. **限并发**：Storage 级 `Semaphore(4)`，元数据补齐 `Semaphore(2)`；避免打满 NAS/IO。
3. **只读必要字节**：标签解析最多读头部 64KB（含大封面扩到 512KB）+ 尾部 128B，绝不整文件下载。
4. **本地标签用 mmap/FileChannel**，避免反复 open/close。
5. **快照比较在内存做**：一次读出该 Storage 全部快照到 Map，避免逐条查 DB。
6. **增量不解析未变更项**：这是 ≤10s 的关键。
7. **取消**：所有循环 `ensureActive()`；取消时阶段 A 已完成的部分保留，阶段 B 直接停。
8. **strm / 播放列表**：解析是纯文本，本地读、无网络；500 首应在 1s 内完成。
9. **兜底杠杆（2026-11-04 复核补充，`10 §3`）**：若阶段 A 仍超时——主因通常是 WebDAV 深目录**串行**逐层 PROPFIND（数百层 × 每层一个 RTT）——启用**同 Storage 内目录级并行走查**（`Semaphore(4~8)` 并发 PROPFIND）；仅按需开启，避免打满 NAS。

> 基准机配置与实测口径写入 03-12 的测试矩阵；若冷扫超时，优先延长阶段 B 而非阻塞阶段 A。

## 11. 错误码（本模块新增/使用）

| 码 | 触发 | 处理 |
|---|---|---|
| `E_SCAN_TAG_PARSE` | 标签损坏 / 非预期格式 | 降级文件名兜底，**不中断扫描** |
| `E_SCAN_PROBE_MISMATCH` | 扩展名与 magic bytes 不符 | 按真实格式解析，仍失败则跳过该文件并汇总 |
| `E_SCAN_RANGE_FAILED` | `ByteRangeCapability` 读失败 | 阶段 B 跳过，保留阶段 A 骨架 |
| `E_SCAN_STORAGE_UNREACHABLE` | 整个 Storage 连不上 | 该 Storage 标 `UNREACHABLE`，其他 Storage 继续 |
| `E_SCAN_CANCELLED` | 用户取消 | 正常结束，返回已完成进度 |
| `E_SCAN_ENCODING` | 文件名/标签编码异常 | 回落 GBK；再失败**跳过该文件并计入失败汇总**（`failure_log`），不中断整轮扫描（对齐 03-03 B16；不使用 `UNSUPPORTED_SCHEME` 状态，2026-11-04 修正，`10 §2 R9`） |

**失败汇总**：`ScanProgress.errors` 收集 `(path, code, detail)`，扫描结束后 UI 展示「N 项失败」并可展开查看、批量重试。上游消息经 `DriverCtx.errDetail` 透传。

## 12. 关键时序

### 12.1 首次添加 WebDAV 并扫描
```
StorageRepo.add → Driver.init（03-02 AuthMode 协商）
 → ScanCoordinator.scan(FULL)
 → 阶段 A：walk → Track 骨架 → upsertBatch → UI 立即可见
 → 阶段 B：后台 ByteRangeCapability 补标签/封面 → 逐条 upsert → UI 刷新
 → 写 scan_snapshot
```

### 12.2 增量扫描
```
App 启动 / 下拉刷新
 → 读 snapshot 到内存 Map
 → 列目录（refresh=false）
 → 比较 (size, modified)：一致则跳过
 → 差异项 → TrackFactory → upsertBatch
 → 缺失项标 UNREACHABLE → 更新 snapshot（≤10s）
```

### 12.3 元数据补齐被取消
```
阶段 B 协程 ensureActive() → CancellationException
 → 已补齐条目保留，未补齐条目维持 tagCompleteness=0.2
 → 下次扫描按快照中 completeness 标记继续
```

## 13. 边界条件清单

| # | 条件 | 期望行为 |
|---|---|---|
| B01 | 标签解析失败 | 仍入库（文件名兜底），不抛、不中断 |
| B02 | 扩展名 `.mp3` 实为 FLAC | 按 magic bytes 解析，记录 `PROBE_MISMATCH` |
| B03 | 时长未知 | 不过滤短时长规则，`durationMs=0`，UI 显示 `--:--` |
| B04 | 0 字节文件 | 入库，播放时由 03-06 判错并跳下一首 |
| B05 | 内嵌封面 > 5MB | 压缩到 512×512，超限则回落同目录封面 |

## 15. 明确禁止事项

1. 禁止为解析标签下载整个网络音频文件（一律 `ByteRangeCapability` 读头部）。
2. 禁止因单个文件解析失败中断整轮扫描。
3. 禁止删除「本次没扫到」的 `Track`（只标 `UNREACHABLE`）。
4. 禁止在阶段 A 阻塞等待网络元数据。
5. 禁止逐条 Room insert（必须批量事务）。
6. 禁止在 `:scanner` 里直接实现 `Driver` 或 `OkHttp` 调用（经能力接口 / 委托）。
7. 禁止让扫描协程无限并发（必须 `Semaphore`）。
8. 禁止把凭据或完整 URL 写进扫描日志。
