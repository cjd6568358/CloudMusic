## 1. 职责与边界

| 做 | 不做 |
|---|---|
| SSDP 发现 + 手动指定 DMR，汇成同一设备列表 | 不做 DMS（不把手机曲库共享出去） |
| `CastUriResolver`：决定推给 DMR 的 URI | 不做手机作为 DMR 被投（PRD §13 #4） |
| AVTransport / RenderingControl SOAP 控制 | 不解码音频、不转码 |
| nanohttpd 本地代理（本地文件投屏 / 无直链形态音源取流 / 直链回落） | 不为 `url` 态直链的本机播放启代理；`proxy` 态本机播放必须启（2026-11-06 修正，`16 §3`） |
| 断连回落本机、直链失败回落代理 | 不做多房间组播同步 |

**单一活动输出**：本机 / 蓝牙 / DLNA 同一时刻只有一个生效（架构 §6）。

## 3. `CastUriResolver` —— 投屏 URI 决策表（★核心）

```kotlin
class CastUriResolver @Inject constructor(
    private val settings: SettingsRepository,
    private val proxy: LocalHttpStreamProxy,
    private val registry: DriverRegistry,
) {
    /** 返回推给 DMR 的 URI + 是否需要启动本地代理 + 回落候选 */
    suspend fun resolve(track: Track): CastUri
}

data class CastUri(
    val uri: String,
    val viaProxy: Boolean,
    val fallback: CastFallback = CastFallback.NONE,
    val directProbePassed: Boolean = false,
)
enum class CastFallback { NONE, PROXY_ON_FAILURE }
```

### 3.1 决策表（含 03-02 补充的 `DirectLinkCapability`）

| `Link.kind` | 音源 | 决策 | `uri` | 代理 |
|---|---|---|---|---|
| `LOCAL` | 本地音乐 | **必须代理**（DMR 读不到手机文件系统） | `http://{手机IP}:{port}/t/{token}` | ✅ 启动 |
| `URL` | strm 直链、播放列表 URL 条目、WebDAV 302 直链 | **原始 URL 原样直推** | `Link.url` | ❌ 不启动 |
| `PROXIED` + `DirectLinkCapability.directUrl()` 返回非 null | WebDAV 匿名可读 / 签名直链 | **直推探测通过的 URL** | `directUrl()` | ❌ 不启动 |
| `PROXIED` + `directUrl()` 返回 null | WebDAV 需鉴权、SFTP/FTP/NFS | 走代理 | `http://{手机IP}:{port}/t/{token}` | ✅ 启动 |
| `TEXT` | strm 虚拟内容（V0.1 不产生） | 退化为代理 | 代理 URL | ✅ 启动 |

> **架构 §7.1 需补注**：原表只按三态划分；03-02 引入 `DirectLinkCapability` 后，`PROXIED` 需先探测一次再决定。本表为最终口径。

### 3.2 决策流程

```
resolve(track)
 → link = driver.link(obj)                       // 重新构建，不缓存 Link
 → if (!settings.preferDirectLink && kind != LOCAL) → 按上表但强制代理（调试开关）
 → when (link.kind) {
      LOCAL  → proxy.ensureStarted(); CastUri(proxy.urlFor(track), viaProxy=true)
      URL    → preProbe(link.url) ?: markFallback; CastUri(link.url, fallback=PROXY_ON_FAILURE)
       PROXIED→ if (settings.forceWebdavProxy || driver.config.preferProxy) CastUri(proxy.urlFor(track), viaProxy=true)
                  else (driver as? DirectLinkCapability)?.directUrl(obj)
                  ?.let { preProbe(it); CastUri(it, fallback=PROXY_ON_FAILURE) }
                  ?: CastUri(proxy.urlFor(track), viaProxy=true)
      TEXT   → proxy.ensureStarted(); CastUri(proxy.urlFor(track), viaProxy=true)
   }
```

`preProbe(url)`：用 OkHttp **不带任何鉴权头**发一次 `HEAD`，2s 超时；2xx/3xx 才记 `directProbePassed=true`。探测结果按 `(url, track.updatedAt)` 缓存，避免每首歌都探。**探测失败不阻止直推**，只是把 `fallback` 标为 `PROXY_ON_FAILURE`（因为有些 DMR 能拉、手机拉不通）。

> **★ 2026-11-06 第十五批落地校准（`12 §24` / `16 §5.3 T-P3`）**：本节决策表与流程已变成
> `output-dlna/CastUriResolver.kt` 的可编译代码，T01~T06 由 `DlnaContractTest` 覆盖。
> 但 `Track` 模型（`03-01 §3.4`）**没有 `updatedAt` 字段**，上述缓存键无法直接实现：
> 纯 JVM 阶段按 `url` 缓存放在 `CachingHeadProbe`，`forceWebdavProxy` / `preferDirectLink`
> 变更时由调用方 `invalidate()`（`08 §7` 缓存失效规则）；未来若给 `Track` 增加版本字段，
> 再按 `(url, version)` 扩展，**不改 `CastUriResolver` 的决策语义**。

### 3.3 设置项

| 设置 | 默认 | 作用 |
|---|---|---|
| `preferDirectLink` | `true` | 决策 3 总开关；关掉后除 LOCAL 外全部走代理（调试用） |
| `forceWebdavProxy` | `false` | 03-02 §4.6：让 `directUrl()` 恒返回 null；与驱动级 `config.preferProxy` 取**或**后决定 `PROXIED` 曲目是否探测直链（03-01 §4，2026-11-04 修正，`10 §2 R6`） |
| `manualDmrHistory` | `[]` | 主动指定过的 DMR，UI 快速选择 |

## 4. DMR 设备来源（两路汇聚）

### 4.1 SSDP 广播发现

```
M-SEARCH * HTTP/1.1
HOST: 239.255.255.250:1900
MAN: "ssdp:discover"
MX: 3
ST: urn:schemas-upnp-org:device:MediaRenderer:1
```

- 用 `DatagramSocket` 发多播，`MX=3` 等待 3s 收集响应；`ST` 也试 `urn:schemas-upnp-org:service:AVTransport:1` 以覆盖不规范设备。
- 响应头 `LOCATION` → 设备描述 URL；`USN` / `SERVER` 用于去重。
- 必须持有 `WifiManager.MulticastLock`（`acquire()` 在发现开始、`release()` 在结束/退出投屏）。
- 发现结果按 `USN` 去重，超时 5s 后返回列表。

### 4.2 主动指定 DMR（A7，★竞品没有的能力）

```kotlin
data class ManualDmrSpec(
    val host: String,                 // IP 或域名
    val port: Int? = null,            // 可空：用常见端口探测
    val descriptionUrl: String? = null,   // 直接给完整 URL 时优先用
    val label: String = "",
)
```

```
ManualDmrSpec
 ├ descriptionUrl 非空 → 直接 GET
 └ 否则按候选 URL 依次 GET：
     http://{host}:{port}/description.xml
     http://{host}:{port}/devicedesc.xml
     http://{host}:{port}/rootDesc.xml
     http://{host}:8200/rootDesc.xml      （常见 DMR 端口）
     http://{host}:49152/description.xml
   → 第一个返回 200 且含 <device> 的即为目标
 → 构造与 SSDP 同类型的 DmrDevice（来源标记 MANUAL）
```

- 适配「不支持组播」「跨网段」「已知设备想快速连接」。
- UI 里手动设备与发现设备**进同一个列表**，仅用标签区分来源；`manualDmrHistory` 持久化。
- 手动指定失败时给出明确原因（连接超时 / 非 MediaRenderer / XML 解析失败），不静默。

## 5. 设备描述 XML 解析

`GET {descriptionUrl}` → `<root><device><serviceList><service>`：

| 字段 | 取值 |
|---|---|
| `friendlyName` | `<friendlyName>` |
| `baseURL` | `<URLBase>`；缺失时用 descriptionUrl 的 scheme+host |
| AVTransport | `serviceType` 含 `AVTransport:1` 的 `<controlURL>` / `<eventSubURL>` / `<SCPDURL>` |
| RenderingControl | 同上，取 `RenderingControl:1` |

**拼 URL 规则**：`controlURL` 可能是相对路径（`/AVTransport/control`）或绝对 URL；相对时与 `baseURL` 拼接，注意尾斜杠归一化。**不同设备的大小写、命名空间前缀都要兼容**（同 03-02 WebDAV 的 W3 规则）。

## 6. SOAP 控制

### 6.1 动作表

| 动作 | service | 参数 |
|---|---|---|
| `SetAVTransportURI` | AVTransport | `InstanceID=0`, `CurrentURI`, `CurrentURIMetaData` |
| `Play` | AVTransport | `InstanceID=0`, `Speed=1` |
| `Pause` / `Stop` | AVTransport | `InstanceID=0` |
| `Seek` | AVTransport | `InstanceID=0`, `Unit=REL_TIME`, `Target=hh:mm:ss` |
| `GetPositionInfo` | AVTransport | `InstanceID=0` → `RelTime` / `TrackDuration` / `TrackURI` |
| `GetTransportInfo` | AVTransport | → `CurrentTransportState` |
| `SetVolume` / `GetVolume` | RenderingControl | `InstanceID=0`, `Channel=Master`, `DesiredVolume` |

### 6.2 `SetAVTransportURI` 报文模板

```xml
POST {avTransportControlUrl} HTTP/1.1
HOST: {host}:{port}
CONTENT-TYPE: text/xml; charset="utf-8"
SOAPACTION: "urn:schemas-upnp-org:service:AVTransport:1#SetAVTransportURI"

<?xml version="1.0" encoding="utf-8"?>
<s:Envelope xmlns:s="http://schemas.xmlsoap.org/soap/envelope/"
            s:encodingStyle="http://schemas.xmlsoap.org/soap/encoding/">
  <s:Body>
    <u:SetAVTransportURI xmlns:u="urn:schemas-upnp-org:service:AVTransport:1">
      <InstanceID>0</InstanceID>
      <CurrentURI>{uri}</CurrentURI>
      <CurrentURIMetaData>{escapedDidlLite}</CurrentURIMetaData>
    </u:SetAVTransportURI>
  </s:Body>
</s:Envelope>
```

- `SOAPACTION` 头**必须**带且带引号；部分设备严格校验。
- `CurrentURIMetaData` 里的 DIDL-Lite 需 **XML 转义**（`<` → `&lt;`）后作为文本，或用 CDATA（先测设备兼容性，默认转义）。
- 错误响应（HTTP 500 + `<UPnPError><errorCode>`）→ 解析 `errorCode` 映射成 `E_OUT_SOAP_*`，带上游描述到 UI。

### 6.3 DIDL-Lite 元数据

```xml
<DIDL-Lite xmlns="urn:schemas-upnp-org:metadata-1-0/DIDL-Lite/"
           xmlns:dc="http://purl.org/dc/elements/1.1/"
           xmlns:upnp="urn:schemas-upnp-org:metadata-1-0/upnp/">
  <item id="{trackId}" parentID="-1" restricted="1">
    <dc:title>{title}</dc:title>
    <dc:creator>{artist}</dc:creator>
    <upnp:artist>{artist}</upnp:artist>
    <upnp:album>{album}</upnp:album>
    <upnp:class>object.item.audioItem.musicTrack</upnp:class>
    <res protocolInfo="http-get:*:{mime}:{contentFeatures}" duration="{hh:mm:ss.SSS}">{uri}</res>
    <upnp:albumArtURI>{coverUrl}</upnp:albumArtURI>
  </item>
</DIDL-Lite>
```

`contentFeatures` 按格式生成：`DLNA.ORG_OP=01;DLNA.ORG_CI=0;DLNA.ORG_FLAGS=01700000000000000000000000000000`；`mime` 由 `IDataSource.mimeHint()` 或扩展名映射（mp3→audio/mpeg、flac→audio/flac、m4a→audio/mp4）。封面本地时走 `/cover/{token}`，网络封面用原始 URL。

## 7. 播放状态同步

| 方式 | 默认 | 说明 |
|---|---|---|
| 轮询 `GetPositionInfo` | ✅ V0.1 默认 | 每 1s 取 `RelTime` / `TrackDuration` / `CurrentTransportState`，推给 UI |
| GENA 订阅 `eventSubUrl` | 可选增强 | 部分设备不支持或回调到不了手机，失败自动退回轮询 |

- 曲目结束（`CurrentTransportState=STOPPED` 且 `RelTime≈TrackDuration`）→ 通知 `PlayerController.next()`，重新 `resolve()` 并 `SetAVTransportURI`。
- 轮询连续 3 次超时 → 判定设备失联 → §11 回落本机。

## 8. nanohttpd 本地流代理（本地文件投屏 / 无直链形态音源 / 直链回落）

> **★ 2026-11-05 纯 JVM 契约层已落地（`12 §16`）**：`:output-localproxy` 模块把本节 §8.2 的 Range / 响应头、§8.3 的 token、§8.4 的启动条件做成可编译代码（`RangeResponder` / `TokenRegistry` / `ProxyStartPolicy` / `InMemoryLocalHttpStreamProxy`），13 个单测覆盖 §13 **T10 / T11 / T12** 与「每请求独立 `IDataSource`」（`10 §2 R8`）。**nanohttpd 服务本体、局域网 IP 绑定与真机并发连接仍属 Android 侧**；`CastUriResolver` / SSDP / SOAP（§3~§6）属 `:output-dlna` / `:output-router`，未在本批实现。**2026-11-06 复核（`16 §3` / C-06）**：`ProxyStartPolicy` 原只建模投屏队列输入；**第十二批已落地** `localPlaybackKind` 与 ④ 触发器，并补 T23/T24 单测（`12 §21`），投屏侧语义零回归。

成熟轻量库定案：**nanohttpd**（架构 §14 #3；不手写 `Range`）。

```kotlin
class LocalHttpStreamProxy : NanoHTTPD(0) {   // 端口 0 = 随机可用端口
    override fun serve(session: IHTTPSession): Response { /* 见下 */ }
}
```

### 8.1 路由

| 路径 | 返回 |
|---|---|
| `GET /t/{token}` | 当前/指定 Track 的字节流 |
| `HEAD /t/{token}` | 同 GET 的头部，无 body（**DMR 常先发 HEAD**） |
| `GET /cover/{token}` | 本地封面（DIDL-Lite `albumArtURI`） |

### 8.2 响应头（DLNA 兼容关键）

```
HTTP/1.1 200 OK  /  206 Partial Content
Content-Type: audio/flac
Content-Length: {len}
Accept-Ranges: bytes
Content-Range: bytes {start}-{end}/{total}     ← 仅 206
transferMode.dlna.org: Streaming
contentFeatures.dlna.org: DLNA.ORG_OP=01;DLNA.ORG_CI=0;...
getcontentFeatures.dlna.org: 1                ← 响应请求该头时
```

- **必须支持 `Range: bytes={start}-`**，返回 206 + `Content-Range`（DMR 拖动进度全靠它）。
- 必须支持 `HEAD`（不少 DMR 先探再拉）；`HEAD` 与 `GET` 头部一致。
- `Content-Length` 未知（strm 直链）时不伪造；用 `chunked` 或 `-1` 并让设备自行处理。
- 多段 Range（`bytes=0-100,200-300`）V0.1 可不支持，返回整段 200 并记录兼容日志。

### 8.3 token 与回源

```kotlin
data class ProxyEntry(val trackId: String, val link: Link, val expiresAt: Long)
```

- `token` 随机 16 字节 hex、短时效（默认 10 分钟），只映射当前队列内曲目；**不暴露真实路径/凭据**。
- 请求到达 → `TokenRegistry.resolve(token)` → 拿到 `Link` → **每个 HTTP 请求各自经 `DataSourceAdapter.from(link)` 新建一个 `IDataSource`**（它是单流有状态对象，**禁止跨请求共享实例**；DMR 常并发多连接，2026-11-04 补注，`10 §2 R8`）→ 按 Range 偏移 `readAt` 读取 → 响应结束 `close()`。
- 即「**本机播放与投屏共用同一套取流原语**」，不写第二套网络栈（架构 §7.2）。
- `LOCAL` 曲目 token 失效/退出投屏时立即回收；`requireReference=true` 的句柄在响应结束时 `close()`。

### 8.4 启动条件（2026-11-06 修正：补 ④，`16 §3`）

```
仅当满足任一条件时才 start()：
  ① 当前投屏队列中存在 LOCAL 曲目
  ② 投屏的 PROXIED 曲目无匿名直链（directUrl() 为 null，见 §3.1 第 4 行）
  ③ 某曲目直连失败需要回落代理
  ④ 本机播放 proxy 态曲目（WebDAV 鉴权流等；引擎舱无字节流入口，
     只能经代理 URL 回环自取，13 §3 / 03-06 §5）
  ⑤ preferDirectLink=false（调试）或 forceWebdavProxy=true
纯直链（url 态）投屏与本机播放 → 不启动代理，省电目标不变
```

- 绑定地址：局域网 IP（不是 `127.0.0.1`，DMR 要能访问；本机回环取流也经同一 IP:port，不另开实例）；随机端口，退出即 `stop()`。
- 生命周期：退出投屏停服 + 释放 `MulticastLock` + token 全失效 + 关闭所有 `IDataSource`；本机播放结束后若不再有 `proxy` 态需求，同样按需停服。
- `:output-localproxy` 的 `ProxyStartPolicy` 当前以投屏队列为输入（`fallbackNeeded` / `anyViaProxy` / `queueKinds` / 调试开关，已覆盖 ①②③⑤ 的投屏语义），**④ 已由第十二批落地**（C-06 / T-P4，`12 §21`）：新增 `localPlaybackKind` 输入，PROXIED / TEXT 本机播放一律启动代理，URL / LOCAL 不启动。

## 9. 直链失败回落（架构 §7.3）

**触发条件**（满足任一）：

| # | 条件 |
|---|---|
| F1 | `preProbe` 明确返回 401 / 403 |
| F2 | 推 URI 后 `SetAVTransportURI` 返回 SOAP 错误（如 714 / 718） |
| F3 | 连续 3 次 `GetPositionInfo` 超时或 `RelTime` 长时间（>8s）无进展 |
| F4 | 直链过期（`LINK_EXPIRED`，由 03-06 标记） |

**回落动作**（只影响当前曲目）：

```
CastUri.fallback == PROXY_ON_FAILURE
 → proxy.ensureStarted()
 → 重新 SetAVTransportURI(proxy.urlFor(track), 同一 DIDL-Lite)
 → Play → UI 提示「已切换手机转发」
 → 记录 (trackId, 原因) 到 failure_log
```

- **不改变其他曲目的直链策略**：下一首仍按 §3.1 重新决策。
- 回落最多 1 次/曲目；再次失败 → 停止并提示用户（不无限重试）。
- WebDAV 鉴权直链的**默认策略已定案**（`directUrl()` 匿名 HEAD 探测通过才直推，失败按 §9 回落代理）；真实 DMR 兼容性作为 **§13 T20/T21 验收测试**执行，不是文档待定项。

## 10. 输出切换与回落时序

### 10.1 切到 DLNA
```
用户选 DmrDevice（发现或手动）
 → OutputRouter.setActive(DLNA, device)
 → IMediaControl.setEnabled(false)               // 03-07：停本机通知/锁屏控件
 → PlayerController 静音（engine.pause + setVolume(0)，保留队列与进度）
 → CastUriResolver.resolve(currentTrack) → CastUri
 → SoapController.SetAVTransportURI(uri, didl) → Play
 → PositionPoller 启动 → UI 显示设备名与 DMR 进度
```

### 10.2 断连回落本机
```
轮询 3 次超时 / SOAP 失败 / 用户点「回到本机」
 → SoapController.Stop()（尽力而为，失败不阻塞）
 → proxy.stop()、MulticastLock.release()
 → IMediaControl.setEnabled(true) + publishMetadata(...)
  → PlayerController 对**业务队列当前曲目**重新 `resolve + prepare`（投屏期间可能已切歌，旧 handle 已失效，2026-11-04 补注，`10 §2 R7`），再 seek 到 DMR 最后进度恢复本机播放
 → UI 提示「已回到本机播放」
```

### 10.3 切歌（保持 DLNA）
```
PlayerController.next() → resolve(新 Track)
 → 若新曲目是 LOCAL：proxy.ensureStarted()（之前可能没启动）
 → 若新曲目是 URL 且代理已启动：可选择停服以省电（队列后续无 LOCAL 时）
 → SetAVTransportURI → Play → 更新 DIDL-Lite 元数据
```

## 14. 明确禁止事项

1. 禁止为 `url` 态直链的**本机播放**启动 nanohttpd；`proxy` 态（WebDAV 鉴权流等）的本机播放**必须**经 nanohttpd 取流（2026-11-06 修正，`16 §3`）。
2. 禁止把带凭据的 WebDAV URL 原样直推 DMR（会 401，且泄露凭据）；必须先经 `directUrl()` 匿名探测。
3. 禁止把所有曲目一律走代理（违背决策 3）。
4. 禁止在 `SetAVTransportURI` 里传未经 XML 转义的 DIDL-Lite。
5. 禁止手写 HTTP Range 解析（用 nanohttpd，架构 §14 #3）。
6. 禁止无限重试直链回落（最多 1 次/曲目）。
7. 禁止在退出投屏后仍持有 `MulticastLock` 或运行代理。
8. 禁止实现 DMS 或手机作为 DMR 被投（PRD §13 #4）。
9. 禁止让 03-09 蓝牙模块直接改 `OutputRouter`（统一由路由层裁决）。
