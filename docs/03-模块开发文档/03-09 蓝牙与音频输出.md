# 03-09 · 蓝牙与音频输出开发文档

**模块**：`:output-bluetooth`、`:output-router` 中的本机/蓝牙分支
**层**：L1.5（架构文档 §6、§10；PRD §6.3）
**上游契约**：`03-07`（`IMediaControl` 照搬层）、`03-06`（`PlayerController`）、`03-08`（`OutputRouter` 切换）
**下游依赖方**：03-10（输出设备弹窗）
**状态**：V0.1 实现规格

---

## 1. 职责与边界

| 做 | 不做 |
|---|---|
| 监听 A2DP 连接/断开，维护「当前输出设备」状态 | **不做音频通道切换**（系统 A2DP 自动路由） |
| 断开时按「因焦点丢失」语义触发自动暂停（可关） | 不直接调 `PlayerController.pause()`（必须经 03-07 照搬层） |
| 把设备名/连接状态推给 UI 与 `IMediaControl` | 不实现 AVRCP 协议（由系统蓝牙栈读 03-07 的 MediaSession） |
| 与 `OutputRouter` 合并输出状态 | 不做蓝牙配对/设备管理界面 |

**定位说明**：蓝牙在本项目里**不是一个可被选择的输出设备**——系统会自动把音频路由到已连接的 A2DP 设备。本模块只负责**观察与上报**，以及把断连事件交给照搬层裁决。真正可切换的输出只有「本机」与「DLNA」（03-08）。

---

## 2. 模块结构

```
:output-bluetooth/
  BluetoothObserver.kt        // 广播监听 + 状态机
  OutputDeviceState.kt        // 当前输出设备模型
  BluetoothSettings.kt        // 自动暂停开关
:output-router/
  OutputRouter.kt             // 合并本机/蓝牙/DLNA 的唯一活动输出
```

依赖：`android.bluetooth` 系统 API、`BLUETOOTH_CONNECT` 权限（API 31+）、`03-07` 的 `IMediaControl`。

## 3. 状态模型

> **★ 2026-11-05 纯 JVM 契约层已落地（`12 §17`）**：下方状态模型、`OutputRouter`（§7 唯一裁决者）与 §4/§5 蓝牙断连策略已变成 `output-router/` 的可编译代码，15 个单测覆盖 §12 **T01~T09 / T15** 与 B01~B10。**唯一暂停出口**是 `IMediaControl.onFocusChange(FocusChange.LOSS)`，禁止直接调 `PlayerController.pause()`。`BluetoothObserver`（`android.bluetooth` 广播 / `BLUETOOTH_CONNECT`）与 T10~T14 集成、真机用例仍待 Android SDK。
> **实现期决策（`12 §17.2`）**：状态模型与策略合并到 `:output-router`，避免与 `:output-bluetooth` 形成循环依赖；Android 侧广播接收器后期只依赖本模块，不回改契约。

```kotlin
data class OutputDeviceState(
    val activeOutput: ActiveOutput,          // LOCAL | DLNA
    val bluetooth: BluetoothInfo?,           // 已连接的 A2DP 设备（可为 null）
    val routeHint: String = "",              // UI 展示："蓝牙 · Sony WH-1000XM5"
)
data class BluetoothInfo(
    val name: String,
    val address: String,                    // 仅本地展示，不上传、不入日志
    val connectedAt: Long,
    val codec: String? = null,              // V0.2 增强：LDAC/aptX/AAC/SBC
)
enum class ActiveOutput { LOCAL, DLNA }
```

> **蓝牙不进 `ActiveOutput` 枚举**：它只是「本机输出」的一种路由状态。若为它单列枚举，会出现「蓝牙与 DLNA 同时激活」的矛盾态。

`OutputRouter` 输出 `StateFlow<OutputDeviceState>`，UI 只读它，不自己监听蓝牙广播。

## 4. A2DP 广播监听

```kotlin
class BluetoothObserver @Inject constructor(
    private val context: Context,
    private val settings: BluetoothSettings,
    private val outputRouter: OutputRouter,
    private val mediaControl: IMediaControl,
) {
    private val filter = IntentFilter().apply {
        addAction(BluetoothA2dp.ACTION_CONNECTION_STATE_CHANGED)
        addAction(BluetoothA2dp.ACTION_PLAYING_STATE_CHANGED)
        addAction(BluetoothAdapter.ACTION_STATE_CHANGED)
        addAction(AudioManager.ACTION_AUDIO_BECOMING_NOISY)   // 有线耳机拔出也走这里
    }
}
```

| 广播 | 处理 |
|---|---|
| `ACTION_CONNECTION_STATE_CHANGED` `STATE_CONNECTED` | 更新 `BluetoothInfo`，UI 提示「已连接 XX 设备」；**不**改变播放状态 |
| 同广播 `STATE_DISCONNECTED` | 触发 §5 自动暂停；清空 `BluetoothInfo` |
| `ACTION_PLAYING_STATE_CHANGED` | 仅记录，不干预（避免与照搬层重复裁决） |
| `ACTION_AUDIO_BECOMING_NOISY` | 与断开等价处理（有线耳机拔出） |
| `BluetoothAdapter ACTION_STATE_CHANGED` `STATE_OFF` | 视为全部断开 |

**权限**：`BLUETOOTH_CONNECT`（API 31+），运行时申请；未授予时**降级**为只监听 `ACTION_AUDIO_BECOMING_NOISY`（无需权限），UI 不显示设备名但播放不受影响（PRD §9）。
>
> **★ 2026-11-07 落地注（`12 §41` 平台接线 / `12 §43` 解环）**：上段「降级路径」已在
> `app/.../PlaybackService.kt` 的 Android 平台层落地——动态注册
> `ACTION_AUDIO_BECOMING_NOISY` receiver（API 33+ 用 `RECEIVER_NOT_EXPORTED`），
> 并接上 `AudioFocusRequest` / `OnAudioFocusChangeListener`；`onPlay` 先请求焦点，未授予不启动。
> **零新增权限、零新增依赖**，C3 仍 11 项。
> 焦点常量（含 T3 `12 §45` 起三个 `AUDIOFOCUS_GAIN*` 变体逐项对映）映射到 `FocusChange.*`，统一经
> `IMediaControl.onFocusChange` → `FocusPolicy` 裁决 → `PlayerControllerHandle.pauseFromFocus()`
> （§5 正式链；`LOSS` 不自动恢复、`LOSS_TRANSIENT` 收到 GAIN 自动恢复、`CAN_DUCK` 只降音量，
> 按 `03-07 §4` 状态机）。bind 由 `PlayerController.init` 用内部 `HandleAdapter` 完成，
> `MediaModule` 只提供 `@Singleton` 实例；第三十四批（`12 §43`）撤销了自建句柄与
> `provideMediaControl(runtime)` 写法，解除 **P0 DI 依赖环**并实跑构建验证。
> **第三十七批（`12 §46`）补充**：该动态 receiver 的事件不再直接下发 `LOSS`，
> 而是先经 `BluetoothOutputPolicy` 按 §5 裁决（`autoPauseOnDisconnect` 热更新 /
> DLNA 豁免 / 去重，见 §5 落地注）；`03-07 §12 T03` 的生产链路已由 `12 §44`（C-15）接通。
> **★ 2026-11-08 第五十六批（`12 §61.29`）**：蓝牙 ACL 连接状态广播 +

## 5. 断连自动暂停（关键约束：走照搬层）

```
STATE_DISCONNECTED / ACTION_AUDIO_BECOMING_NOISY
 → if (!settings.autoPauseOnDisconnect) return      // 用户可关
 → if (outputRouter.activeOutput == DLNA) return    // 投屏中不由蓝牙裁决
 → mediaControl.onFocusChange(FocusChange.LOSS)     // ★交给 03-07 照搬层裁决
 → 照搬层 → PlayerControllerHandle.pauseFromFocus()
 → 03-06 setPlaybackState(PAUSED, ...)
```

> ⚠️ **禁止** `bluetoothObserver` 直接调 `PlayerController.pause()`（03-07 §8、§13 禁止事项）。原因：照搬层需要维护「是否因焦点暂停」的恢复标记；直接暂停会导致来电恢复、蓝牙回连后状态错乱。

**回连不自动恢复**：与永久 `AUDIOFOCUS_LOSS` 语义一致（03-07 §4 B01），用户需手动播放。

> **★ 2026-11-07 第三十七批落地注（`12 §46`）**：上链已在 `app/.../PlaybackService.kt`
> 接通 `ACTION_AUDIO_BECOMING_NOISY` → `BluetoothOutputPolicy.onEvent(BECOMING_NOISY)`。
> 两道前置判定由策略执行：`autoPauseOnDisconnect`（每次事件读 `SettingsAccess.current()`
> **热更新**）与 `router.activeOutput == LOCAL`（DLNA 豁免），另有 `pauseInFlight` 去重（B04），
> 唯一暂停出口仍是 `IMediaControl.onFocusChange(FocusChange.LOSS)`；用户手动播放后
> `notifyPlaybackResumed()` 复位去重（回连本身不复位，T05 / B05）。
> **权限口径**：`BLUETOOTH_CONNECT` 已在 Manifest 11 项清单内，但 V0.1 未做运行时动态申请，
> 故 `permissionGranted=false` 按 §8 B01 降级，只处理无需权限的 BECOMING_NOISY；
> 蓝牙 ACL `STATE_DISCONNECTED` / `ADAPTER_OFF` / `CONNECTED` 广播与设备名上报仍待 L2 授权流程。

## 6. AVRCP 与元数据

本模块**不实现 AVRCP**。元数据链路：

```
03-06 PlayerController.publishMetadata(track, cover)
 → 03-07 IMediaControl → MediaSession 元数据
 → 系统蓝牙栈 → 耳机 / 车机显示（标题/艺人/专辑/封面/进度）
```

03-09 只提供一个辅助字段 `BluetoothInfo.name` 给 UI 显示「正在输出到 XX 设备」。

| V0.1 | V0.2 增强 |
|---|---|
| 设备名、连接状态 | 编码格式显示（LDAC / aptX / AAC / SBC）：需 `BluetoothA2dp` 隐藏 API 或 `AudioManager` 参数，风险高，暂不做 |

## 7. 与 `OutputRouter` / DLNA 的交互

| 场景 | 行为 |
|---|---|
| 本机播放 + 蓝牙连接 | `activeOutput=LOCAL`，`bluetooth` 非空，UI 显示设备名 |
| 切到 DLNA | `activeOutput=DLNA`；**忽略**此期间的蓝牙断开事件（§5）；`IMediaControl.setEnabled(false)` 由 03-08 负责 |
| DLNA 回落本机 | 03-08 调 `OutputRouter.setActive(LOCAL)`；重新读取当前 A2DP 状态刷新 `BluetoothInfo` |
| 蓝牙断开同时来电 | 03-07 照搬层去重，只暂停一次（03-07 §11 B06） |
| 飞行模式 | 蓝牙可用与否由系统决定；本模块不主动关闭蓝牙，不弹网络错误 |

> `OutputRouter` 是**唯一裁决者**：03-08 切 DLNA、03-09 上报蓝牙状态，都只改它，不互相直接调用（03-08 §14 #9）。

## 9. 错误码

| 码 | 触发 | 处理 |
|---|---|---|
| `E_OUT_BT_PERMISSION` | `BLUETOOTH_CONNECT` 未授予 | 降级为只监听 `AUDIO_BECOMING_NOISY`，不阻断播放 |

| `E_OUT_BT_STATE` | 广播状态异常（未知 state 值） | 记日志、忽略，不改变输出状态 |

## 11. 时序

### 11.1 蓝牙连接
```
BluetoothA2dp STATE_CONNECTED
 → BluetoothObserver 更新 BluetoothInfo
 → OutputRouter.emit(LOCAL + bluetooth)
 → UI 显示「蓝牙 · XX」；IMediaControl 无需动作
```

### 11.2 蓝牙断开（自动暂停）
```
STATE_DISCONNECTED
 → 检查 autoPauseOnDisconnect / activeOutput
 → IMediaControl.onFocusChange(LOSS)
 → 03-07 照搬层 → pauseFromFocus() → 03-06 PAUSED
```

### 11.3 切 DLNA 期间的蓝牙事件
```
OutputRouter.setActive(DLNA)（03-08）
 → 期间 STATE_DISCONNECTED → §5 提前 return
 → 回落本机后重新读取 A2DP 状态
```

## 13. 明确禁止事项

1. 禁止 App 侧切换音频通道（系统 A2DP 自动路由，PRD §6.3）。
2. 禁止直接调 `PlayerController.pause()`（必须经 03-07 照搬层裁决）。
3. 禁止实现 AVRCP 协议或私有 BLE 协议。
4. 禁止接入厂商耳机 SDK / HiCar / Android Auto 深度适配（PRD §8）。
5. 禁止把蓝牙设备地址写进日志、曲库 DB 或任何上报。
6. 禁止把蓝牙列为与 DLNA 并列的 `ActiveOutput`（它是本机输出的路由状态）。
7. 禁止蓝牙回连自动恢复播放。
8. 禁止在投屏期间用蓝牙事件改变 `activeOutput`。
