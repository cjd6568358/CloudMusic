## 2. R8 / ProGuard 规则（★关键，写错直接崩）

竞品 so 的 JNI 符号硬绑定 Java 全限定类名（`Java_com_netease_cloudmusic_android_sdk_playerengine_*`），**R8 混淆或移除这些类会直接 `UnsatisfiedLinkError`**。

> **★ 2026-11-05 已落地并校准（`13 §8`）**：完整规则文本在 **`engine-legacy/proguard-rules.pro`**（纯静态规则，未建舱源码 / 未提取 so / 未实现 slot，路线 A 边界不变）。下方为骨架摘要；示意包名 `module.player.**` / `ui.**` 已收窄为实证精确类，并补上原示意**漏掉**的 `receiver.MediaButtonEventReceiver` 与 `media.NEAudioDevice$...`。


> ⚠️ **原示意包名的两处实证修正**：① `03-07 §2.1` 的 `AudioFocusKeeper` / `AudioFocusHolderWrapper` 只是字符串常量、无类定义，焦点状态机真实类名仍待 jadx（`13 §6 #8`）；② `com.netease.cloudmusic.utils.audiofocus.a` 实为青少年模式 Tab 拦截器，不是焦点状态机，不要按包名照搬。
> **C1 已实现原注要求的校验**（`tools/check-engine-abi.py`）：12 个精确类逐条存在、4 个包族通配存在、从 4 个入口 so 的 **202 个 `Java_*` 导出符号**反推所属类并确认 keep 覆盖，缺任一项即 `FAIL`（dev/release 均阻断）。dev 实测输出 `R8 keep 规则已落地：12 个精确类 + 4 个包族通配 + 202 个 Java_* 符号类全覆盖`。

**资源保护**：照搬资源通过 XML / 数字 id 引用，`shrinkResources` 可能误删。在 `:ui-legacy/res/values/keep.xml` 声明：

```xml
<resources xmlns:tools="http://schemas.android.com/tools"
    tools:keep="@anim/legacy_*,@drawable/legacy_*,@layout/legacy_*,@color/legacy_*" />
```

> 前提是按 03-10 §3.4 方案 A 统一加了 `legacy_` 前缀；若未加前缀，需逐项在 `tools:keep` 列出映射表里的 `legacy_name`。

## 4. 一次性 ABI 验收（汇总 03-06 §6）

| 项 | 内容 |
|---|---|
| A1 | `nm -D --defined-only` 导出 `Java_*` 符号 ↔ 重建类方法逐一对照，缺一即阻断 |
| A2 | 每个 so `readelf -d` 查 `DT_NEEDED`，递归闭包全部在 167 个清单内 |
| A3 | 真机黄金用例 G01~G09（播放/暂停/seek/时长/ENDED/Range/解码失败/20 分钟后台/native crash 恢复）**★ `12 §50`：DEEP RUN —— native 6 so 加载 / setDataSource / prepareAsync / 焦点 / Play 真机跑通且零崩溃，但取流未通、0 个 active track、G01~G09 仍 NOT RUN，不判 PASS、不冻结舱** |
| 产物 | `assets/ENGINE-FINGERPRINT`（源 APK 9.6.20 + **18 个打包集 so** 的 SHA-256 + 验收结论；167 个仅为提取侧上限，C6 指纹只覆盖打包集） |

**标签解析不做 native ABI 验收**：03-04 §6.2 已定案采用 `JAudioTaggerTagReader` + `MediaMetadataRetriever`，不照搬竞品 native 库。`05-Native库实测分析.md §3` 的 ELF 实测表明：相关 so（`liblive_disk_scanner.so` / `libnecmMediaInfo.so` / `libnecmMediaCommon.so`）**JNI 导出均为 0**，而 `libscannative.so` 实为华为 HMS ScanKit 扫码库，均不可用。此项从 ABI 验收清单中移除，不属于遗留待办。

**so 打包范围（P1-R3，2026-11-04 实测；★2026-11-05 已拍板采纳闭包打包；★spike #1 实证修正）**：`DT_NEEDED` 递归闭包（入口 = 4 个带 JNI 导出的库）实测 **14 个 so / 18.1 MiB**（含 `libc++_shared.so`，见下），加上 Java 层按名加载的 4 个软解器（`necmMP3Dec` / `necmAACDec` / `necmFlacDec` / `necmMediaCodecJDec`，spike #1 指令级实证，实测合计 481 KB）共 **18 个 / 18.5 MiB**；全量 167 个为 **125.6 MiB**，其中约 **107.5 MiB（86%）** 与播放无关（声网 / NERTC / Cronet / Hermes / 元宇宙 / 安全 SDK 等）。

> **2026-11-05 spike #1 修正（`13 §2`）**：原 17 个清单把 `libc++_shared.so` 误列入「系统库」白名单。实测它是 `libncmplayerengine.so` 等 5 个库的 `DT_NEEDED` 直接依赖，NDK 明确要求随 APK 打包（缺失即 `dlopen failed`），竞品也自带该文件（968.7 KB）。已移出 `tools/elf_probe.py` 的 `SYSTEM_LIBS`、计入打包集。**R3「只打闭包」的决策口径不变，仅修正闭包定义**；C1 递归闭包因此由 13 → 14 个。
