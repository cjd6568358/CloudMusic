## 2. R8 / ProGuard 规则（★关键，写错直接崩）

竞品 so 的 JNI 符号硬绑定 Java 全限定类名（`Java_com_netease_cloudmusic_android_sdk_playerengine_*`），**R8 混淆或移除这些类会直接 `UnsatisfiedLinkError`**。

```proguard
# 1. 舱内所有类保持原名、不被移除
-keep class com.netease.cloudmusic.android.sdk.playerengine.** { *; }
-keep class com.netease.cloudmusic.module.player.** { *; }
-keep class com.netease.cloudmusic.receiver.mediabutton.** { *; }
-keep class com.netease.cloudmusic.ui.** { *; }

# 2. 所有 native 方法与声明类
-keepclasseswithmembernames class * { native <methods>; }

# 3. JNI 回调 / 反射入口
-keep class * implements com.example.cloudmusic.engine.api.IMusicEngine { *; }
-keep class * implements com.example.cloudmusic.media.IMediaControl { *; }

# 4. 播放页照搬自定义 View（XML 反射构造）
-keep class com.netease.cloudmusic.** extends android.view.View { *; }
-keepclasseswithmembers class * {
    public <init>(android.content.Context, android.util.AttributeSet);
}

# 5. 枚举名（Room / DataStore 存字符串名）
-keepclassmembers enum * { *; }

# 6. 崩溃/日志中不落凭据
-assumenosideeffects class android.util.Log {
    public static int v(...); public static int d(...);
}
```

> ⚠️ 上面 `com.netease.cloudmusic.module.player.**` 等 keep 包名是**按 03-07 §2.1 实证类名归纳的示意**，落地时须用 jadx 反编译结果校准实际包名；漏 keep 一个类即运行时 `UnsatisfiedLinkError`。C1 的 JNI 符号对照脚本应同时校验「每个 `Java_*` 符号对应的类都在 keep 规则覆盖范围内」。

**资源保护**：照搬资源通过 XML / 数字 id 引用，`shrinkResources` 可能误删。在 `:ui-legacy/res/values/keep.xml` 声明：

```xml
<resources xmlns:tools="http://schemas.android.com/tools"
    tools:keep="@anim/legacy_*,@drawable/legacy_*,@layout/legacy_*,@color/legacy_*" />
```

> 前提是按 03-10 §3.4 方案 A 统一加了 `legacy_` 前缀；若未加前缀，需逐项在 `tools:keep` 列出映射表里的 `legacy_name`。

## 4. 一次性 ABI 验收（汇总 03-06 §6）

| 项 | 内容 |
|---|---|
| A1 | `nm -D --defined-only` 导出 `Java_*` 符号 ↔ 重建类方法逐一对照，缺一即阻断 |
| A2 | 每个 so `readelf -d` 查 `DT_NEEDED`，递归闭包全部在 167 个清单内 |
| A3 | 真机黄金用例 G01~G09（播放/暂停/seek/时长/ENDED/Range/解码失败/2h 后台/native crash 恢复） |
| 产物 | `assets/ENGINE-FINGERPRINT`（源 APK 9.6.20 + 167 个 so 的 SHA-256 + 验收结论） |

**标签解析不做 native ABI 验收**：03-04 §6.2 已定案采用 `JAudioTaggerTagReader` + `MediaMetadataRetriever`，不照搬竞品 native 库。`05-Native库实测分析.md §3` 的 ELF 实测表明：相关 so（`liblive_disk_scanner.so` / `libnecmMediaInfo.so` / `libnecmMediaCommon.so`）**JNI 导出均为 0**，而 `libscannative.so` 实为华为 HMS ScanKit 扫码库，均不可用。此项从 ABI 验收清单中移除，不属于遗留待办。

**so 打包范围（P1-R3，2026-11-04 实测；★2026-11-05 已拍板采纳闭包打包）**：`DT_NEEDED` 递归闭包（入口 = 4 个带 JNI 导出的库）实测仅 **13 个 so / 17.1 MB**，加上 Java 层按名加载的 4 个软解器（`necmMP3Dec` / `necmAACDec` / `necmFlacDec` / `necmMediaCodecJDec`，dex 字符串实证，实测合计 481 KB）共 **17 个 / ~17.6 MB**；全量 167 个为 **125.6 MB**，其中 **108.5 MB（86%）** 与播放无关（声网 / NERTC / Cronet / Hermes / 元宇宙 / 安全 SDK 等）。

**★ 拍板结论**：`:engine-legacy/src/main/jniLibs/arm64-v8a/` **只放下列 17 个**；167 保持为**提取侧上限**与 C1 ③ 的对照全集，**闭包外 150 个不进 APK**，留在 `analysis/` 备查。G01~G09 出现缺库时按需追加，但必须同步回写本表、`ENGINE-FINGERPRINT` 与 C6 指纹。

| 组别 | so（实测文件名） | 大小 |
|---|---|---|
| 入口 ×4 | `libncmplayerengine.so` 814 KB、`libaudioplayer.so` 191 KB、`libnmplaylist.so` 424 KB、`libNMCommonCache.so` 302 KB | 1.7 MB |
| 音频链路 | `libncmaudioplayer.so` 1145 KB、`libncmusbaudio.so` 282 KB | 1.4 MB |
| 解码 / 特效 | `libffmpeg.so` 6503 KB、`libneaudioeffects.so` 1837 KB、`libneaudioeffect_core.so` 1690 KB、`libneaudioaiif.so` 422 KB | 10.2 MB |
| AI 音效推理 | `libMNN.so` 2116 KB、`libMNN_Express.so` 726 KB | 2.8 MB |
| 持久化 | `libsqlite3x.so` 1033 KB | 1.0 MB |
| 按名加载软解器 ×4 | `libnecmMP3Dec.so` 81.7 KB、`libnecmAACDec.so` 248.1 KB、`libnecmFlacDec.so` 17.6 KB、`libnecmMediaCodecJDec.so` 133.9 KB | 481 KB |

> `libEGL.so` / `libGLESv3.so` 为闭包引用但属**系统库**，不打包。`libneaudioeffects` / `libneaudioaiif` / `libMNN*` 即使「V0.1 不做音效」也必须在打包集内（playerengine 直接依赖，`05 §5`）。spike #0 完成后用实测 `System.loadLibrary` 清单复核本表，脚本 `tools/check-engine-abi.py`（C1 ③）以此表为唯一基准。详见 `10-技术架构评估.md §2 R3`。

> 运行时**不做**指纹校验（决策 1：so 不升级，一次性开销）。

## 7. 合规风险与处置（★必须如实记录）

架构文档 §4.4 已提示：直接使用竞品 native so、Java SDK 层、图标/字体/文案，存在**著作权与 EULA 风险**，且与项目 AGPL-3.0 开源在权利状态上并不自洽。

| 场景 | 处置 |
|---|---|
| **个人自用 / 侧载**（当前目标） | 风险可控；`NOTICE.md` 如实声明来源与权利状况；素材仅作开发期占位 |
| **公开发布仓库 / 分发 APK** | ① 完成素材全量替换 ② 法务评估竞品 so 的可分发性 ③ 若不可分发，启用架构预留的**逃生舱**：重写实现 `IMusicEngine` 的 `:engine-opensource`（FFmpeg + Media3/ExoPlayer），上层零改动切换 |
| **上架应用商店** | 额外需处理包名/应用名/图标无第三方品牌特征、隐私政策、权限说明 |

`NOTICE.md` 至少包含：竞品样本指纹（9.6.20 / versionCode 9006020）、提取的 so 清单与 SHA-256、Java SDK 与播放页资源的来源说明、"仅供个人学习与自用、权利归原作者"的声明、第三方开源依赖许可证清单。
