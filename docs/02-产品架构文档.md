## 0. 架构第一原则（由用户决策推导，全文不得违背）

| # | 决策（来自 PRD §13） | 架构含义 |
|---|---|---|
| A1 | 匹配场景**像素级复制竞品代码和 so**，避免 bug | 播放内核、解码、队列状态机、音频效果**不重写**，直接复用竞品 native 层；但必须用**隔离舱**包起来 |
| A2′ | 播放内核 so「可升级」**降级为一次性搬迁开销**（用户后续确认：未来解包升级可能性不大） | 引擎层与业务层仍用 `IMusicEngine` 门面解耦、产物物理隔离；**不投入**自动解包升级工具链，仅保留换开源引擎的逃生舱 |

| A4 | 竞品技术栈**升级到最新**，去掉老旧兼容代码 | 详见 §9 技术栈升级对照表；剔除多进程 AIDL、DataBinding、Fresco、Cronet、WMRouter、RN(Hermes) |
| A5 | **仅 arm64** | 只解包 `arm64-v8a` 的 167 个 so；Gradle 固定 `abiFilters`，不打包其他架构 |
| A6 | **开源 AGPL-3.0** | 依赖选型需兼容；竞品 so 的来源、权利状态写入 `NOTICE.md` |
| A7 | DLNA **主动指定目标 DMR** | 设备来源 = SSDP 广播发现 **＋** 手动输入 IP:Port / description URL，两条路径汇到同一控制接口 |
| A8 | 数据源驱动**参考 OpenList-zig** | Driver 体系、Obj/Link/Storage 模型、`Link` 三态交付 1:1 借鉴；见 §3 |
| A9 | 投屏 **直链优先**：除本地音乐外全部直链（用户后续确认） | `CastUriResolver` 按 `Link` 形态决策；本地代理缩窄为「仅本地文件 + 直链失败回落」，见 §7 |

> **优先级规则（用户 2026-11-04 二次确认）**：当 **A1（照搬竞品）与 A4（技术栈升级）冲突时，A1 优先**。已确认 ① 唱片动画、③ 音频焦点两层照搬竞品；照搬范围内允许保留竞品的 View 体系与自研 MediaSession / 焦点实现，技术栈升级只在照搬范围之外生效。

> **合规张力（A6 × A1）**：项目以 AGPL-3.0 开源，但照搬的竞品 so / Java SDK / 播放页素材为**专有二进制，权利状态不明**，二者在权利上并不自洽。个人自用侧载风险可控；公开发布仓库或分发 APK 前须法务评估，或启用 `:engine-opensource` 逃生舱。详见 `03-12 §7`、`NOTICE.md`。此条不阻断当前开发，但列为发布阻断项。

**一条主线**：竞品是「在线曲库 App」，它没有「本地/网络挂载/strm 数据源」这个概念；它的播放内核经 `DataProvider` 接收**音源定位符（URL / 本地路径 / fd），由 native 自行拉流**（spike #1 实证，`13 §3`：`PlaybackDataSource` 是预加载/缓存配置类、不是数据源接口，Java 层不喂字节流）。本项目架构的本质就是：

> **用 OpenList-zig 式的插件化数据源层，把任意来源收敛为 `Link` 三态，再翻译成竞品内核认识的 URL / 本地路径 / 代理 URL；播放内核的输出由统一的输出路由层决定送到本机 / 蓝牙 / DLNA。**

这个「数据源 ←→ 内核 ←→ 输出」的三段解耦，同时满足了「照搬 so」「插件化数据源」「输出可切换」三个看似冲突的要求。自研 `IDataSource`（`readAt` 按偏移读）**不再是引擎主取流路径**，它服务于本地代理回源（§7.2）与扫描 Range 读（03-04 §3）。

**依赖方向**：上层单向依赖下层；`L2 引擎舱` 通过 `IMusicEngine` 门面**反向不感知**任何上层；`L3 数据源层` 只认识 `Link`，不认识播放内核；`L2.5` 是唯一同时认识 `Link` 和舱内 `DataProvider` 契约的地方。

**单进程模型**：竞品是「主进程 + `:play` + 5 个 MpService + AIDL」（分析报告 §2），本项目按 A4 **简化为单进程 + 一个前台服务** `PlaybackService`，用协程 + StateFlow 取代 AIDL。理由：本地播放器没有插件容器/动态页隔离需求，AIDL 是历史包袱。播放稳定性靠前台服务 + `WAKE_LOCK` + 独立线程池保障，不靠进程隔离。

**播放页照搬的落地路径（决策 ①）**：APK 实测播放页为 **View 体系** —— `activity/PlayerActivity` + 自定义唱片 View + `res/anim/` 下 **2,227 个 XML 动画**（public.xml 收录 2,232 条 anim，`06 §1`；含 `interpolator` / `repeatCount` / `pivotX` 等参数）+ 大量混淆 drawable（`a.xml`、`a0.xml`、`a.webp`…）；另有 `VinylDIYEditActivity` 与 `vinylVisible` / `vinyl_song` 等黑胶相关字符串。**资源名已全部混淆，无法按文件名挑选**：必须从 `PlayerActivity` 反编译代码里取出引用的资源 ID → 反查 `public.xml` 得到混淆文件名 → 导出资源 → 连同自定义 View 与动画代码一起搬。本项目采用**整页照搬**（独立 Activity / View 子树，由 Compose 导航经 `AndroidView` 或 Activity 跳转接入），其余页面仍纯 Compose。代价：局部混用两套 UI 框架，但被限制在这一屏。

## 3. 数据源抽象层（★参考 OpenList-zig，核心扩展点）

### 3.1 设计来源

`OpenList-zig` 有两套等价实现，本项目取其**接口语义**而非代码：

- Go 版 `internal/driver/driver.go`：`Driver = Meta + Reader`，`Reader = List(ctx, dir, args) + Link(ctx, file, args)`；能力通过 `Config` 位（`OnlyProxy / NoLinkURL / LocalSort / NoCache / NoUpload`）声明。
- Zig 版 `src/driver.zig`：手写 vtable（`{ptr, vtable}`），方法集 `list / details / link / makeDir / move / rename / remove / put`，可选能力为 `null`。
- 模型 `src/model.zig`：`Obj`（目录项）、`File`（单文件）、`Link`（交付形态）、`LinkArgs`、`Storage`（持久化挂载记录）、`Addition`（驱动私有配置）。

本项目 V0.1 **只读**，砍掉写方法（makeDir/move/rename/remove/put），保留 `List / Get(details) / Link`，能力位保留 `OnlyProxy / NoLinkURL / NoCache / PreferProxy`。

### 3.2 契约（Kotlin，接口签名级）

> 本节代码块为**示意**；字段与类型的**权威定义一律以 03-01 §3 / 03-06 §4 为准**，两处不一致时以 03-xx 为准修正本文（2026-11-04 复核已将 `headers` 类型对齐为 `List<Header>`，见 `10 §2 R12`）。

```kotlin
// :core-model —— 与 OpenList-zig model.zig 一一对应
data class Obj(
    val name: String,
    val size: Long = 0,
    val isDir: Boolean = false,
    val modified: Long = 0,          // Unix 秒
    val sign: String = "",           // 不透明 token，link 时回传
    val thumb: String = "",
    val hashInfo: HashInfo? = null,
)

/**
 * 交付形态三态（对齐 OpenList-zig model.zig:116 Link）—— ★全架构枢纽
 *  - url        : 内核可直连的 http/https 直链（strm、WebDAV 302）
 *  - localPath  : 本机文件路径，内核/SAF 直接读（本地驱动）
 *  - proxy      : 必须由「本地 HTTP 流代理」转发（WebDAV 鉴权流、SFTP/FTP/NFS 流）
 *  - text       : 内存中的虚拟文件内容（strm 虚拟目录场景）
 */
data class Link(
    val url: String = "",
    val headers: List<Header> = emptyList(),
    val localPath: String? = null,
    val localSize: Long = 0,
    val proxy: Boolean = false,
    val text: String? = null,
    val contentLength: Long = 0,
    val requireReference: Boolean = false, // 需持有底层句柄（对齐 Go SyncClosers）
)

data class LinkArgs(val method: String = "GET", val headers: List<Header> = emptyList(), val redirect: Boolean = false)

// :datasource-api
interface Driver {
    val config: DriverConfig
    suspend fun init(ctx: DriverCtx)                       // 校验配置/登录/恢复会话
    fun drop()                                             // 释放连接（须容忍 init 失败后调用）
    suspend fun list(dir: Obj, refresh: Boolean = false): List<Obj>
    suspend fun get(path: String): Obj?                     // 按路径取单文件
    suspend fun link(file: Obj, args: LinkArgs): Link      // ★统一交付点
}

data class DriverConfig(
    val name: String,
    val onlyProxy: Boolean = false,      // 一切走代理
    val noLinkUrl: Boolean = false,      // 不返回直链
    val noCache: Boolean = false,
    val localSort: Boolean = true,
    val preferProxy: Boolean = false,
) { fun mustProxy() = onlyProxy || noLinkUrl }

object DriverRegistry {                                  // 对齐 op.RegisterDriver
    typealias DriverFactory = (Storage, Addition) -> Driver  // ★需 Storage.id 与配置，见 03-01 §4.1
    fun register(type: String, factory: DriverFactory)
    fun create(type: String, storage: Storage, addition: Addition): Driver
}
```

**新增一种协议 = 新增一个 `:datasource-xxx` module + 一条 `register`，不改 L2/L4/L5 一行代码**（PRD §4 原则 2）。

### 3.3 各驱动实现要点（逐条对照 OpenList-zig 源码）

| 驱动 | 参考文件 | 必须照搬/借鉴的行为 | Link 输出 |
|---|---|---|---|
| **Local** | `local.zig` / `drivers/local/driver.go` | 路径沙箱（归一化后二次校验根，防 `..` 逃逸，注释见 local.zig:7-13）、隐藏文件开关、符号链接默认不跟随、缩略图路径即 `/d/...?type=thumb&sign=` | `localPath` |
| **WebDAV** | `webdav.zig` / `drivers/webdav/driver.go` | ① **AuthMode 三态协商**（none→401→basic/digest，webdav.zig:86-97，Go `NewClient` 初始恒为 NoAuth）；② **PROPFIND Depth:1 跳过首个 `<response>`**（否则出现幽灵重复目录，webdav.zig:16-18）；③ **href 尾斜杠归一化**（Nextcloud 有/nginx 无）；④ **命名空间前缀剥离**（`D:href`/`d:href`/`href`）；⑤ 自签证书 `tls_insecure_skip_verify`；⑥ `Link` 支持 `Redirect` 取 302 后真直链（driver.go:74-88） | `url` 或 `proxy` |
| **Strm** | `strm.zig` / `drivers/strm/driver.go` | `paths` 每行 `key:dst` / 裸 `dst`、单 key 时 **autoFlatten**、filter 后缀→同名 `.strm` 虚拟文件（size=链接文本长度）、download 后缀透传、`minSize` 过滤、媒体后缀默认 `mp3,flac,aac,wav,ogg,m4a,wma,alac...` | `text` / `url` |
| **Playlist** | 借鉴 strm 展开语义 | `.m3u/#EXTM3U/#EXTINF`、`.m3u8`、`[playlist]` `.pls`；条目支持相对路径（相对播放列表所在目录）、绝对路径、URL；递归展开、去重、失效条目标记 | 展开为子 `Obj` |
| **SFTP** | `drivers/sftp/driver.go` | `clientReconnectOnConnectionError` 断线重连、`Open` 后 `RateLimitFile` 包装、`RequireReference=true` 持有句柄 | `proxy` |
| **FTP** | `drivers/ftp/driver.go` | 编码转换（mahonia，`Encoding` 字段）、`CwdList` 模式、`RetrFrom(offset)` 实现 RangeReader、连接用完 `Quit` | `proxy` |
| **NFS** | 预留 | 接口占位，`Config.onlyProxy=true` | `proxy` |

> **关键洞察**：OpenList-zig 的 `Link` 三态（`url` / `local_path` / `proxy`+`text`）恰好对应本项目 Android 端的三条取流路径 —— 直连、本地文件、本地 HTTP 代理。§3.2 的 `Link` 因此成为全架构的枢纽数据结构，`L2.5 DataSourceAdapter` 只按这三态分派，不关心具体协议。

### 3.4 `.strm` 与播放列表的语义边界

- `.strm`：**一个文件 = 一首歌**，内容是「第一行非空非 `#` 的 URL」，仅 `http/https`；文件名兜底解析 `艺人 - 标题`。
- `.m3u/.m3u8/.pls`：**一个文件 = 一组曲目**，展开为多个 `Obj`；条目可指向本地相对文件、绝对文件或 URL（URL 条目退化为 strm 语义）。
- 二者可嵌套：播放列表里的 URL 条目 → 按 strm 处理；指向 `.strm` 的相对路径 → 按 strm 解析。
- 不因一次播放失败删除条目，只标记「链接失效」并保留（PRD §5.2）。

## 4. 播放内核「引擎舱」设计（★照搬 + 一次性搬迁，A1/A2′ 落地）

### 4.1 为什么必须做隔离舱

分析报告 §5 已指出：竞品 native 库的 JNI 符号**硬绑定 Java 类名**，例如
`Java_com_netease_cloudmusic_android_sdk_playerengine_AudioPlayerUnit_nativePlay`。
这意味着：**照搬 so 就必须连同 Java SDK 层一起搬，且包名/类名一个字都不能改**（否则 `UnsatisfiedLinkError`）。
若让这层污染自研代码，整个项目将被锁死在竞品包结构里。故设计独立 module 隔离。

### 4.2 舱内结构

```
:engine-legacy/
├── 包名严格锁定 com.netease.cloudmusic.android.sdk.playerengine.*   ← 不可改
│   PlaybackEngine / AudioPlayerUnit / Playback / PlaybackDataSource
│   SourceConfig / DataProvider / PlaybackListener / MusicInfo
│   （来源：jadx 反编译 classes*.dex → **重建为可编译源码**，像素级复制）
├── jniLibs/arm64-v8a/            ← 仅 167 个 arm64 so（A5）
│   libncmplayerengine.so  libncmaudioplayer.so  libaudioplayer.so
│   libffmpeg.so  libnecmMP3Dec/AACDec/FlacDec  libMediaCodecJDec
│   libneaudioeffects.so  libncmusbaudio.so  libnmplaylist.so ...
├── META-INF/ENGINE-FINGERPRINT   ← 版本指纹：源 APK versionName + 各 so SHA-256
└── (对外) 仅暴露一个稳定门面 → :engine-api 的 IMusicEngine
```

### 4.3 稳定门面（自研包名，升级不变量）

```kotlin
// :engine-api —— 我们的包名，永不变；让上层与竞品包结构彻底解耦
interface IMusicEngine {
    fun prepare(source: EngineSource, config: EngineConfig): EngineHandle
    fun play(handle: EngineHandle)          / fun pause(handle) / fun stop(handle)
    fun seek(handle, positionMs: Long)      / fun setVolume(handle, v: Float)
    fun positionMs(handle): Long            / fun durationMs(handle): Long
    fun state(): Flow<EngineState>          // 单实例门面无参版；权威签名以 03-06 §4 为准
    fun attachDataSource(handle, ds: IDataSource)  // ★注入取流句柄：proxy 态供代理回源；url/localPath 经 EngineSource 直传（C-05，16 §4）
    fun setQuality(...) / fun attachAudioEffect(...)  // 竞品能力透传
    fun release(handle)
}
/** 引擎舱侧的取流契约（自研）；舱内 EngineAdapter 经 DataProvider 适配，13 §3 */
interface IDataSource {
    fun open(offset: Long): Long            // 返回总长度，-1 未知
    fun readAt(offset: Long, buf: ByteArray, len: Int): Int   // 支持 Seek/Range
    fun close()
    fun mimeHint(): String
}
```

- `EngineAdapter`（舱内）把 `IMusicEngine` 调用翻译成 `PlaybackEngine.nativeEngine*`（`13 §7` 实证的三层 API 取最新层），音源经 `LegacyDataSourceBridge : DataProvider` 交付 URL / 本地路径 / 代理 URL；`IDataSource` 仅用于代理回源（`16 §3`）。
- **上层只依赖 `IMusicEngine` / `IDataSource`**，不 import 任何 `com.netease.*` 类。

### 4.4 一次性搬迁流程（A2′ 降级后的定案）

> **用户决策（2026-11-04）**：未来解包升级 so 的可能性不大，**按一次性开销计算**。
> 因此不再投入 `unpack-engine.sh`、版本 diff、自动 ABI 回归这套升级工具链；
> 稳定门面 `IMusicEngine` 与舱隔离**仍保留**（成本仅一层接口，且是未来换开源引擎/合规替换的逃生舱），
> 但其定位由「升级通道」改为「解耦边界」。

```
竞品 APK（一次性）
  → apktool d -s 取 lib/arm64-v8a/*.so（167 个，A5）
  → jadx 反编译 classes*.dex 的 playerengine 子树
      → 按原包名/类名重建为可编译 Java/Kotlin 源码（用户决策 2）
  → 人工修补反编译失真（混淆类名、泛型擦除、lambda/内部类、资源引用），裁剪依赖闭包
  → 实现 EngineAdapter（IMusicEngine ↔ 竞品 PlaybackEngine；Link 三态 ↔ DataProvider）
  → 一次性 ABI 验收：
      ① JNI 符号齐全（对照 so 的 Java_* 导出表）
      ② so 依赖闭包完整（readelf -d 查 DT_NEEDED，防 dlopen 失败）
      ③ IMusicEngine 黄金用例在真机通过（播放/暂停/seek/时长/结束回调/各格式解码）
  → 冻结 :engine-legacy，提交 ENGINE-FINGERPRINT（源 APK 版本 + 各 so SHA-256）备查
```

- **不采用打包 dex 片段**（用户决策 2）：黑盒不可改、无法补适配层、依赖闭包可能拖出小半个 APK、与 AGPL 开源冲突更大。个别确实无法重建的内部类只允许作为**临时例外并单独登记**，不作为计划内方案。
- **前置工具**：`tools/` 现有 apktool / smali / baksmali / 7z / adb，**缺 jadx**；阶段 3 开工前确认打包机工具链并补入（按用户既有环境处理，不联网下载）。
- **逃生舱保留**：未来若因合规需要替换，只要重写一个实现 `IMusicEngine` 的 `:engine-opensource`（FFmpeg + Media3/ExoPlayer），上层零改动即可切换。这是 A1 与 AGPL 之间的平衡阀，不做额外投入。

> ⚠️ **合规**：舱内为第三方代码，`:engine-legacy` 单独标注来源与权利状态写入 `NOTICE.md`；项目开源（AGPL-3.0），若未来公开发布需法务评估。

## 5. 数据源适配与播放链路（L2.5 时序）

```
用户点「播放 Track」
 → PlayerController.resolve(track)
 → DriverRegistry 找到该 Track 的 Driver
 → driver.link(obj, LinkArgs) → Link（三态之一）
 → 按 Link.kind 交付（2026-11-06 按 spike #1 实证修正，`13 §3` / `16 §3`）：
       url        → 引擎经 DataProvider.getUrl() 自取该 URL（native HTTP，不经代理、不经 IDataSource）
       localPath  → 引擎经 getLocalPath()/openLocalFd() 直读本机文件（不经代理）
       proxy      → 先 proxy.publish(trackId, link) 拿本地代理 URL（代理按 §7.2 ④ 启动），
                    引擎回环自取；代理每请求经 DataSourceAdapter.from(link) 新建 IDataSource 回源
       text       → 扫描期已展开为 URL 条目；若直接播放则同 proxy 处理
  → IMusicEngine.prepare(source, config) + attachDataSource(handle, ds) → play
  → OutputRouter 根据当前输出设备决定是否改走 DLNA（见 §6）
```

**本机取流只有 `proxy` 态经过本地 HTTP 代理**（`url` / `localPath` 由引擎自取，见 §7.4）。WebDAV 鉴权流（无匿名直链）与 SFTP/FTP/NFS 属 `proxy` 态——这是 spike #1 实证引擎舱**无法消费 Java 字节流**后的必然结论，修正原「本机播放完全不经代理」口径（`16 §3`）。投屏时 `CastUriResolver` 另做一次 URI 决策（除 `LOCAL` 与无匿名直链的 `PROXIED` 外一律直链，03-08 §3.1）。

`IDataSource.readAt(offset, ...)` 是**本地代理回源与扫描 Range 读的取流原语**：这两处的 Seek/拖动进度都归约为「按偏移读」，与 OpenList-zig `RangeReader` / `Source.readAt`（model.zig:203-257）的设计同源；它**不再处于引擎主取流路径**（原「与竞品内核 `PlaybackDataSource_native*` 语义一致」的表述已被 `13 §3` 证伪——`PlaybackDataSource` 是预加载/缓存配置类）。

## 6. 输出设备路由（本机 / 蓝牙 / DLNA）

```
                    ┌─────────────────┐
   IMusicEngine ──▶ │  OutputRouter   │──▶ LocalOutput      (AudioTrack/AAudio，默认)
   (统一内核)        │  单一活动输出    │──▶ BluetoothRoute   (系统 A2DP 自动路由)
                    └────────┬────────┘──▶ DlnaOutput       (DMC：内核静音，DMR 播放)
                             │               └ CastUriResolver：直链优先 / 本地文件走代理(A9)
                             │
                    DeviceSource（两路汇聚，A7）
                     ├ SsdpDiscovery   (M-SEARCH 广播 + MulticastLock)
                     └ ManualDmrSpec   (手动输入 IP:Port 或 description URL) ★新增
```

> 图中 `BluetoothRoute` 仅为「本机输出的一种路由状态」示意，**不是与 DLNA 并列的可选输出**（`ActiveOutput` 枚举只有 LOCAL / DLNA 两值，见 `03-09 §3`）；蓝牙由系统 A2DP 自动路由，App 不切音频通道。

- **同一时刻只有一个活动输出**；切换 DLNA 时本机内核暂停/静音，手机退化为遥控器，UI 显示设备名与 DMR 回传的播放状态。
- **蓝牙**：依赖系统 A2DP 自动路由，App 不切音频通道；`BluetoothA2dp` 广播监听断开 → 自动暂停（可关）；元数据通过 MediaSession 推给 AVRCP（标题/艺人/专辑/封面/进度）。
- **回落**：DLNA 断连 → 自动回落本机播放并提示（PRD §6.2）。

### 6.1 DLNA 主动指定 DMR（A7，重点）

竞品只做 SSDP 广播发现；本项目新增**手动指定**通道，适配「不支持组播 / 跨网段 / 已知设备想快速连接」：

```
ManualDmrSpec(host, port) 或 (descriptionUrl)
 → 直接 HTTP GET 设备描述 XML（跳过 SSDP 发现）
 → 解析 <device>/<serviceList>，取 AVTransport + RenderingControl 的
    SCPDURL / controlURL / eventSubURL（拼 baseURL，处理相对路径）
 → 构造 DmrDevice（与 SSDP 发现产出的对象同类型）
 → 走同一套 SoapController：
    SetAVTransportURI(CastUriResolver.resolve(track), DIDL-Lite 元数据)
        └ 决策 3：除本地文件走代理 URL 外，其余均为原始直链 URL
    → Play / Pause / Stop / Seek / GetPositionInfo / GetVolume / SetVolume
 → 订阅事件（可选 GENA）或轮询 GetPositionInfo 同步进度
```

两条来源产出的 `DmrDevice` 进入**同一设备列表**，UI 不区分来源（仅标注「手动」）。多播仅在 SSDP 发现期间持有 `MulticastLock`，退出即释放。

### 6.2 媒体焦点层照搬竞品（决策 ③，替代 Media3 主导）

用户确认：音频焦点 / 媒体按键 / MediaSession 这条链路**照搬竞品**，不引入 Media3 作为主导者。

**APK 实证**（`analysis/strings/` 中的类与常量）：竞品是一整套自研焦点状态机，不是简单的 `MediaSessionCompat`：

- `AudioFocusKeeper` / `AudioFocusHolderWrapper` / `module/player/monitor/AudioFocusInfo`（焦点抢占与恢复）
- `module/player/utils/AudioFocusChangeRecord`（焦点变更记录）
- `receiver/MediaButtonEventReceiver` + `receiver/mediabutton/*`（线控 / 媒体按键）
- `aidl/MediaSessionCallbackParam`（跨进程回调参数）、`ui/AudioFocusDialogHelper`（焦点冲突提示）
- 常量：`AUDIOFOCUS_GAIN / LOSS / LOSS_TRANSIENT / LOSS_TRANSIENT_CAN_DUCK`、`AudioFocusRequestCompat`

**照搬范围**：核心状态机（抢占 → 暂停 / duck → 恢复）、按键分发、通知 / 锁屏 / AVRCP 元数据语义、状态转换条件与提示文案。

**剔除范围**（A4，历史兼容包袱）：`AndroidHonorReleaseMediaSession`（荣耀适配）、`HiCarMediaSessionDelegate` / `CarMediaSessionHandlerDelegate`（车机）、`GameAudioFocusListener`（游戏房）、`WebMediaButtonReceiver`（WebView 音频）、`MediaButtonABManager`（AB 实验）、`PlayerLogTrace`（日志追踪）、redux 与多进程 AIDL 胶水。

## 7. 投屏 URI 决策与本地 HTTP 流代理（A9：直链优先）

> **用户决策 3（2026-11-04）**：除本地音乐用成熟 HTTP 代理外，**其余音源全部直链**。
> 即 DMR 能自己按 URL 拉的就不经手机中转：省掉手机的中转带宽与耗电，也避免 strm 带签名的直链被二次转发破坏。

### 7.1 CastUriResolver（投屏 URI 决策，落在 `:output-dlna`）

`SetAVTransportURI` 之前按 `Link` 形态决定推给 DMR 的 URI：

| `Link` 形态 | 音源 | 推给 DMR 的 URI | 理由 |
|---|---|---|---|
| `localPath` | **本地音乐** | `http://手机IP:port/t/{token}`（本地代理） | DMR 无法访问手机文件系统，必须代理 |
| `url` | strm 直链、WebDAV 可直连 URL、播放列表 URL 条目 | **原始 URL 原样直推** | DMR 自己拉，不经手机 |
| `proxy` / `text` | WebDAV 鉴权流（`directUrl()` 探测不可得）、SFTP / FTP / NFS（V0.2+ 预留） | 仍走本地代理 | 无 HTTP 直链形态（或匿名探测不可得），DMR 无从访问，**属协议限制而非策略选择** |

> **03-08 补注（实现期发现）**：`kind=PROXIED` 的 WebDAV 曲目需先经 03-02 的 `DirectLinkCapability.directUrl()` 匿名探测——返回非 null 则直推该 URL，否则走本地代理；SFTP/FTP/NFS 必然走代理。最终决策表见 `03-08 §3.1`。本决策（直链优先）不变。

> ⚠️ **WebDAV 鉴权风险（需在真机验证）**：DMR 直连 WebDAV 时**不会携带 Authorization 头**。
> 处理方式：优先让 WebDAV 侧给出可直连的签名/匿名 URL；不可得时**默认仍直推 + 失败自动回落代理**（§7.3），
> 并在设置里提供「WebDAV 强制走代理」开关。此项列入 `03-08` 的真实 DMR 兼容性测试矩阵。

### 7.2 本地代理（本地文件投屏 / 无直链形态音源取流 / 直链回落）

成熟库定案：**nanohttpd**（专注嵌入式/Android 的极轻量 HTTP 服务器，协议解析由库兜住，不手写 `Range`）。

```
LocalHttpStreamProxy（nanohttpd，绑定局域网 IP + 随机端口，按需启动）
  GET /t/{token}          → 本地文件字节流（按 Range 偏移读）
  GET /cover/{token}      → 本地封面（DIDL-Lite albumArtURI）
  Range / If-Range        → 206 Partial Content（DMR 拖进度必需）
  Content-Type            → DataSource.mimeHint() / 扩展名
```

- **token**：短时效、随机，只映射当前队列内的本地曲目，不暴露真实路径/凭据（对齐 OpenList-zig `sign.Sign`）。
  - **回源**：`token` → `Link`（`LOCAL` 文件，或直链失败回落的 `PROXIED` 源）→ 每请求经 `DataSourceAdapter.from(link)` 新建 `IDataSource`，按偏移 `readAt` 读取，不写第二套网络栈（详见 03-08 §8.3）。
- **启动条件（2026-11-06 修正，`16 §3`）**：满足任一才 `start()`——①投屏队列中存在 `LOCAL` 曲目；②投屏的 `PROXIED` 曲目无匿名直链（`directUrl()` 为 null）；③直连失败需回落；④**本机播放 `proxy` 态曲目**（WebDAV 鉴权流等，引擎只能经代理 URL 取流）；⑤`preferDirectLink=false` / `forceWebdavProxy=true` 调试开关。**纯 `url` 态直链（strm / 302）的本机播放与投屏均不启动代理**，省电目标不变。
- **生命周期**：退出投屏即停服、释放 `WifiManager.MulticastLock`、token 全失效。

### 7.3 直链失败回落

DMR 直连失败（HTTP 401/403/超时、直链过期、`GetPositionInfo` 长时间无进展）→ 自动为**该曲目**切换为代理 URL 并重新 `SetAVTransportURI`，UI 提示「已切换手机转发」。仅回落当前曲目，不改变其他曲目的直链策略。

### 7.4 本机播放取流（2026-11-06 修正）

本机播放按 `Link.kind` 分派（§5）：`url` / `localPath` 由引擎自取、**不经代理**；`proxy` 态（WebDAV 鉴权流、SFTP/FTP/NFS）**必须经本地代理转 URL**（引擎舱无 Java 字节流入口，`13 §3`）。即代理不只服务于 DLNA 输出，也服务于本机播放 `proxy` 态；但纯直链曲目的本机播放仍不启动代理。

## 8. 数据模型与持久化

### 8.1 两层模型

| 层 | 模型 | 说明 |
|---|---|---|
| 数据源层 | `Obj` / `File` / `Link` / `Storage` / `Addition` | 参考 OpenList-zig model，描述「挂载里有什么、怎么取」 |
| 业务层 | `Track` / `Playlist` / `QueueItem` | 统一曲库模型（PRD §5.3），描述「用户看到的一首歌」 |

`Track` 关键字段：`id`（来源+路径/URL 的稳定哈希）、`title/artist/album/duration`、`sourceRef`（→ 可重建 `Link` 的定位符）、`sourceType`、`coverRef`、`tagCompleteness`、`availability`（OK / UNREACHABLE / LINK_EXPIRED / UNSUPPORTED_SCHEME）。

**ID 稳定性**：挂载地址变更时用「来源命名空间 + 相对路径」重算，配合迁移表保留收藏/播放记录（PRD §5.3）。

### 8.2 持久化选型（升级后，见 §9）

| 数据 | 方案 | 理由 |
|---|---|---|
| 曲库 / 歌单 / 队列 / 播放记录 | **Room**（SQLite） | 类型安全、迁移工具成熟；取代竞品 WCDB 加密库（本地无需加密） |
| 数据源配置 / 设置 / 上次队列游标 / **WebDAV 账号密码等凭据** | **DataStore(Proto) 明文存储** | 取代 MMKV；用户决策 ④「个人作品，不需要考虑安全性」，**不引入 Keystore / 加密层**，少一层依赖也少一类国产 ROM 兼容问题；`03-05` 只定字段与序列化 |
| 大对象（封面缓存） | 文件缓存 + Coil 磁盘缓存 | 不入库 |
| 引擎指纹 / so 清单 | `assets/ENGINE-FINGERPRINT` | 随舱升级更新 |

> 竞品用 WCDB(加密 SQLite)+MMKV+Fresco 是历史包袱，按 A4 全部替换，见 §9。

## 10. 线程 / 进程模型（单进程）

| 线程/调度器 | 职责 |
|---|---|
| `Main` | UI / Compose、照搬的 MediaSession / 音频焦点回调 |
| `PlaybackService`（前台，`foregroundServiceType=mediaPlayback`） | 持有 `IMusicEngine` 实例、`OutputRouter`；`LocalHttpStreamProxy` **按需启停**（§7.2） |
| `EngineThread`（单线程，专属） | 所有 `IMusicEngine` 调用**串行化**，避免竞品 native 引擎的线程安全隐患 |
| `IoDispatcher` | 数据源 `list/link`、网络、SAF 读取、扫描 |
| `ScanDispatcher`（限并发，可取消） | 递归扫描、元数据/封面解析；用 `Semaphore` 控并发防 IO 打满 |
| `ProxyDispatcher` | nanohttpd 连接处理（仅代理激活时存在，每连接一个协程） |

- 播放状态用 `StateFlow<PlayerState>` 单向广播给 UI；UI 通过 `PlayerController` 发 intent，不直接碰引擎。
- 引擎舱（C++）内部有自己的解码/输出线程，由舱自己管理，`EngineThread` 仅做串行门控。
- 崩溃恢复（2026-11-04 语义修正，`10 §2 R2`）：单进程下引擎 native crash 即**整个进程退出**，不存在可靠的进程内捕获；恢复机制 = `PlaybackService` 声明 `START_STICKY` → 系统重启服务 → `onCreate` 从 Room 队列游标恢复并保持 PAUSED（03-06 §12.6，含 Android 12+ 后台 FGS 重启限制的降级路径）。相对竞品的多进程隔离，这是**明确的取舍而非能力补齐**；若真机 G09 显示重启体验不可接受，`IMusicEngine` 门面允许未来把 `:engine-legacy` 拆为独立进程（预留，V0.1 不做）。

## 11. 错误处理、日志与错误码

- 统一 `Result<T, CloudMusicError>`；错误码分层：`E_DS_*`（数据源：认证失败/超时/NotFound/NotSupport/编码错）、`E_SCAN_*`（扫描/解析）、`E_ENGINE_*`（解码/输出/ABI 符号缺失）、`E_OUT_*`（DLNA SOAP/蓝牙/代理/直链回落）、`E_LINK_*`（strm 失效/不支持 scheme）。
- **上游可信消息透传**：借鉴 OpenList-zig `Ctx.err_detail`（driver.zig:47-73），驱动可把上游人类可读错误带回 UI，避免笼统「网络错误」。
- 不可用状态机（PRD §5.3）：`OK → UNREACHABLE/LINK_EXPIRED → 恢复自动置 OK`，**灰显但不移除**。
- 日志：结构化、按 `tag`（`[webdav:nas]` / `[dlna:客厅音箱]`）区分；发布版关闭 so 层 verbose；日志不落敏感凭据。
- 每个模块的错误码与上报点在对应 `03-xx` 文档中冻结。
