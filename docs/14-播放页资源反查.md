## 2. 关键实证：`android:tag` 保留了原始语义名

`06 §3` / `03-10 §3` 的前提是「`res/layout` 下文件名全部混淆（`a.xml`/`a0.xml`），无法按文件名挑素材，只能先反编译拿资源 ID 再反查 public.xml」。实测 apktool 解包产物里，layout 根元素普遍带：

```xml
<!-- analysis/decoded/res/layout/gc.xml -->
<androidx.constraintlayout.widget.ConstraintLayout
    android:tag="layout/activity_new_player_vehicle_0" ... >
```

去掉尾部 `_数字` 即得到**原始语义名**。9 个核心入口的映射（`14 §3`）只是 48 个播放页相关 layout 的一部分：

| 混淆文件 | `android:tag` 语义名 |
|---|---|
| `layout/gr.xml` | `activity_player_audio` |
| `layout/gb.xml` | `activity_new_player_land` |
| `layout/gc.xml` | `activity_new_player_vehicle` |
| `layout/c6a.xml` | `layout_player_landscape_vinyl` |
| `layout/bv5.xml` | `layout_land_vinyl` |
| `layout/c5y.xml` | `layout_player_backgroud`（原文拼写如此） |
| `layout/buu.xml` | `layout_item_land_vinyl` |
| `layout/are.xml` | `fragment_mi_miniplayer` |
| `layout/e0g.xml` | `view_vinyl_records` |

**处置**：`06 §3` 的步骤 ① 增加「先扫 `android:tag` 建语义名 → 混淆文件名映射」，`public.xml` 的 id 反查从「唯一路径」降为「交叉校验」。48 个播放页相关映射的完整清单在 `analysis/player-resource-closure.json` 的 `layout_semantic_tags` 字段。

## 3. 入口与递归闭包（工具化）

`tools/player_resource_audit.py` 按 `06 §3 ④⑤⑥` 做 BFS：

1. 解析 `public.xml` → `(type,name) → 0x7f...` 与反向索引；
2. 从入口 layout 的属性值抽 `@type/name`、`@+id/name`、`?attr/name`（`@android:*` 系统资源跳过）；
3. 单文件资源（layout / drawable / anim / …）按 `(type,name)` 找到全部 qualifier 变体的 XML，继续解析；
4. `color / dimen / style / string / bool / integer / array` 等 values 类资源按 `name` 在 `values*/` 定义节点展开其引用；
5. 直到没有新资源，产出 JSON + CSV。

产物（均在 `analysis/`，**不写 `docs/assets-mapping.csv`**）：

| 文件 | 内容 |
|---|---|
| `player-resource-closure.json` | 入口、48 个语义 tag、163 项资源（id / 类型 / 文件 / 是否需导出）、179 条引用边 |
| `player-resource-closure.csv` | 同上的平铺清单，列 `type,name,resource_id,semantic_name,files,origin,export_needed`，供步骤 ⑧ 逐项登记 |
| `smali14/` + `smali14-run.log` | classes14.dex 全量反汇编产物 |
| `player-code-refs-probe.log` / `player-anim-refs.log` | 自定义 View 定位与 anim 段扫描记录 |

仅 1 项 `attr/xml` 未在 `public.xml` 登记（来自 `?attr/xml` 的解析结果），属导出前需人工确认的挂账项，不影响闭包完整性判定。

### 4.1 唱片旋转动画：候选与参数（诚实挂账）

XML 侧闭包里**没有 anim / style 项**（9 个入口 layout 不引用 anim），而 20 个 View 类与全 dex 中播放页相关类都不内联 anim 段 ID —— 说明动画资源由 Activity / Presenter 在运行时注入（或经 R 类字段）。作为替代线索，实测 `res/anim*` 里共有 **40 个「无限循环 rotate」动画**（20 组正/反转 × 变体），参数样例：

```xml
<!-- analysis/decoded/res/anim/ax.xml -->
<set android:interpolator="@android:anim/linear_interpolator" android:duration="10000">
  <rotate android:fromDegrees="0.0" android:toDegrees="-360.0"
          android:pivotX="50.0%" android:pivotY="50.0%" android:repeatCount="infinite" />
</set>
```

- `toDegrees` 全为 `±360.0`，`pivotX/Y` 全为 `50.0%`，插值器为系统线性插值器；
- `duration` 从 `1000` 到 `21600000` 共 20 个不同值成对出现（`10000`、`15000`、`20000`、`25000`、`30000`…）——**静态无法确定哪一个是唱片旋转**，不能凭 `03-10 §3.3` 表格里的「12s」示例推定（实测候选中没有 12000）。
- **挂账**：导出前必须用 jadx 反编译 `PlayerActivity` / `PlayerDiscViewFlipper` 的调用链或真机抓取 `AnimationUtils.loadAnimation` 的 id，才能把具体 anim 加入闭包。这条是 ⑦ 之前的必做项，否则会漏资源导致 `Resources$NotFoundException`。
>
> **★ 2026-11-06 第二十九轮 jadx 复核（`12 §38`）——本挂账的「jadx 反编译」部分已执行**：
> `tools/resolve_player_anim.py` 找到此前搜 `0x7f01xxxx` 得到「0 引用」的**真实原因**——
> 播放页的资源 ID 以 **R 类静态字段**传入 `loadAnimation`（如 `sget p1, Lxj1/a;->e:I`），
> 不是内联常量。全量扫描 `analysis/smali14/` 得 **12 处 `loadAnimation` 调用点 / 4 个唯一静态字段**：
> `n1.g = 0x7f0100ba`、`n1.m = xj1.a.e = v61.a.a = 0x7f0100eb`（`xj1.a` / `v61.a` 由 jadx 从
> `classes3` / `classes20` 反编译，落 `analysis/jadx-anim-rclasses/`）。反查 `public.xml` 得
> **`anim/eb.xml`（scale，132ms）** 与 **`anim/fn.xml`（scale，200ms）** —— **都是缩放动画，
> 不是无限循环 rotate**。另反编译 `PlayerDiscViewFlipper` / `RotationRelativeLayout` /
> `RotationVinylView` 三个 View，确认**无 anim 引用**。
> **结论修正**：唱片旋转**不由 `AnimationUtils.loadAnimation` 加载**，可能走属性动画 /
> 自定义 View Canvas；40 个 rotate 候选（复核仍为 40 个、无 `12000`）**仍需真机或属性动画链路确认**。
> 挂账状态从「待 jadx」更新为「**jadx 已复核，余真机/属性动画链路**」；⑦ 导出前仍须解决。
> `docs/assets-mapping.csv` 保持空表（C4 语义不变），本轮未导出任何素材。
>
> **★★ 2026-11-06 第三十轮最终收口（`12 §39`）——本挂账关闭**：
> 属性动画链路已由 jadx 定向反编译**证实**。`RotationRelativeLayout.init()` 用
> `ValueAnimator.ofFloat(0.0f, 1.0f)` + `LinearInterpolator` + `setRepeatCount(-1)`
> + `setRepeatMode(1)` + `setDuration(yh0.m.b())`；`AnimationHolder.onAnimationUpdate()`
> 把 `getAnimatedFraction() * 360.0f` 传给 `View.setRotation(...)`。
> `PlayerVinylViewHolder` 用两个 `ObjectAnimator`（`discHeadUpRotateAnimation` /
> `discHeadDownRotateAnimation`）做唱针起落，唱片容器字段就是 `RotationRelativeLayout disc`。
> `yh0.m.b()` 实测为 **`20000.0f / getPlaySpeed(...)`**、`c(f) = 20000.0f / f`
> ——**基准周期 20 秒，随播放速度动态变化**。
> **结论**：唱片旋转与唱针起落**全部是纯代码属性动画，不加载任何 `res/anim/` XML**。
> 因此「40 个无限循环 rotate 候选中哪一个是唱片旋转」是**伪命题**：
> 播放页资源闭包**不需要 anim 项**，与本节原观察到的「XML 闭包里没有 anim / style」一致，
> 也不会因漏 anim 导致 `Resources$NotFoundException`。**⑦ 素材导出不再被 anim 阻塞**。
> 注意：候选里恰有 `duration="20000"`，但数值相同只是巧合，不能据此认作唱片旋转。
> `03-10 §3.3` 表格的「12s」示例值**作废**（候选中本就没有 12000）。
> 证据与参数见 `analysis/jadx-player-views/` 与 `analysis/rotation-anim-resolution.json`。
