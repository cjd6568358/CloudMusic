## 1. 为什么需要专门复核

本项目的架构决策经历了**三轮调整 + 一次实现期契约回补**，后一轮推翻前一轮的部分结论，最容易在早期文档里留下"僵尸表述"：

| 轮次 | 决策 | 被推翻/调整的内容 |
|---|---|---|
| 第一轮 | 像素级复制代码和 so、开源 AGPL-3.0、仅 arm64、**so 可升级**、技术栈升级、DLNA 主动指定 DMR、驱动参考 OpenList-zig | — |
| 第二轮 | so 升级降为**一次性搬迁**、DI 定 Hilt、**jadx 重建源码**、**投屏直链优先**（新增 A9 / `CastUriResolver` / nanohttpd） | 推翻「可升级」「全量手机转发」 |
| 第三轮 | 播放页唱片动画**照搬竞品**、音频焦点**照搬竞品**、凭据**明文不加密** | 推翻「Compose Canvas」「Media3 主导」「Keystore 加密」，新增第二个照搬舱 |
| 实现期 | 发现 `Link` 三态不够用 → 新增 `DirectLinkCapability` / `ByteRangeCapability` 两个可选能力，回补 03-01 与架构 §7.1 | 契约缝隙 |

本轮复核就是逐份核对：被推翻的结论是否还有残留、新决策是否在所有相关文档同步、模块与接口签名是否仍能对上。
