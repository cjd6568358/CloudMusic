## 问题

`03-07 §12 T03`「手动暂停 → GAIN 不恢复」的纯 JVM 单测早已存在，但**生产链路不成立**：
`PlaybackService.onPause()` 只调 `runtime.pause()`，`IMediaControl` 无感，`FocusPolicy.resumePending` 残留 →
来电结束后收到 `AUDIOFOCUS_GAIN` 会被误判为「来电恢复」而自动续播。

## 方案：契约演进 C-15（零回归）

`IMediaControl` 是 `03-07 §3` 冻结门面，`:media-legacy` 与 `output-router` 的 `FakeMediaControl` 等测试替身都实现它。
直接加抽象方法会破坏全部实现 → 加**带默认空实现**的方法，既有实现零改动即可编译（与 C-08「带默认参数的 `directUrl`」同款解法）。

| 文件 | 改动 |
|---|---|
| `core-media/.../MediaControlApi.kt` | `fun onPlaying() {}` / `fun onManualPause() {}` + KDoc |
| `core-media/.../InMemoryMediaControl.kt` | 两个既有方法加 `override`，挂到门面类型 |
| `core-media/.../FocusPolicy.kt` | `onPlaying()` 增 `resumePending = false`（避免手动播放后被 GAIN 重复 resume） |
| `app/.../PlaybackService.kt` | `onPlay()` 焦点授予后 `mediaControl.onPlaying()`；`onPause()` 先 `mediaControl.onManualPause()` 再 `runtime.pause()` |
| `core-media/src/test/.../MediaControlContractTest.kt` | +3 单测：门面类型 T03 生产链路 / 手动播放清恢复标记 / 默认空实现零回归 |
| `tools/check_source_contracts.py` | SIGNATURES +2 needle；新增 3 条守护；更新过时 NOTE |
| `docs/03-07 §3` | 登记 C-15 |

**隐式顺序依赖（`§43.4` 挂账）的处置**：`bind()` 仍由 `PlayerController.init` 完成，依赖 `PlaybackRuntime` 被构造。
本批不改绑定方式，改为静态守护断言 `PlaybackService` **同时**注入 `PlaybackRuntime` 与 `IMediaControl`
（注入必触发 `PlayerController` 构造完成 bind）；另断言 `provideMediaControl()` 零参数，防止 DI 环回归。
