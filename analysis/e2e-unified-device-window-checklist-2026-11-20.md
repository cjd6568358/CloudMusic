# 统一真机判读窗口执行清单（2026-11-20）

> 目的：把散落在 `docs/12 §61.232/238/245/252~258` 与既有 runbook 里的 pending-device 项收成一页。
> 设备上线后按 **P0 → P1 → P2 → P3** 顺序逐项打勾。本文件只是**判据索引**，
> 不替代各批 runbook，不新增 adb 能力，也不代表任何一项已经跑过。

## 0. 全局纪律（每项都适用）

1. 端点由用户给裸端口，全程 `adb -s <端点>`；mDNS 常有多个残留，不猜 IP。
2. **不擅自切用户网络**；需要开/关 WiFi、飞行模式、投屏网络时由用户在场操作。
3. MIUI 禁 `INJECT_EVENTS`：页面切换、按钮点击、拖动 seek 全部由用户手动；
   我方只读 logcat / `dumpsys` / `screencap` / Room 库。
4. 取 Room 库用 `adb exec-out run-as com.example.cloudmusic cat databases/cloudmusic.db`，
   并**连同 `-wal` 一起取**；`screencap` 前 `export MSYS_NO_PATHCONV=1`，
   二进制一律走 `adb exec-out`（`adb shell cat` 会损坏）。
5. 判读窗口开始 `svc power stayon true`、收尾 `false`（MIUI Doze 会断网络）；
   DataStore 手术只用 §61.254 runbook 既有步骤，**凭据不写入本文件或日志**。
6. 每项结论按 **PASS / FAIL / PARTIAL / NOT RUN** 登记到证据 JSON；
   静态推断不得写成「已修复」，脚本跑通不等于真机判据通过。

## 5.1 已知源数据缺陷（非 App 解码 bug）

- 标题 `20？？ 长岛 黄昏` / 专辑 `听说？刘若英`：服务器 CUE 原文 **GBK 编码**，原始字节
  `TITLE "20 a3 bf a3 bf 20 b3 a4 b5 ba 20 bb c6 bb e8"`——`a3 bf` 就是全角 `？`，
  源文件里**本身就是两个问号**。WebDAV 驱动 UTF-8→GBK 回落正确（其余中文均正常解码），
  这不是我们的乱码，也不是 UI 渲染问题。
- 处置边界：**不猜字、不伪造标题**。要恢复真实曲名需替换服务器上的 CUE 源文件；
  展示层最多可做「标题含？，源文件已损坏」提示（未实现，需用户拍板）。
